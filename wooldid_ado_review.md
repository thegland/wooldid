# Project Chunk: Improving the Assessment Suite

Let's review the suitability of our assessment suite. One thing I want to be careful with is that we are making appropriate use of pathological data. It's important that wooldid does not fail catastrophically when given pathological input data - defining 'fail catastrophically' as presenting wrong results that look plausibly correct. We want wooldid to either present true correct results, or fail in an observable way. So testing pathological data is useful. But it's also not always the most determintive for checking whether features work as intended when given useful data. So we should make sure that we have these difference cases marked, and should understand scenarios using pathological data as an input as mainly being about answering the question 'does wooldid and this or that feature of it handle the pathological data correctly', rather than as being about answering whether a given feature is functioning optimally (which we may wish to test in other settings). Of course, a perfect distinction can't be drawn between these cases, and edge case failures can reveal deeper errors - but we do need to make sure that we tend to test features using both pathological and non-pathological data. And when we find an error using pathological data, we should inform our diagnosis of the problem based on both that performance and how the feature performs using better behaved input as well. **Short answer.** No reported surface ever prints a non-zero reference-period effect: the event-study margins run over `subpop(targetflag==1 & _t in window)`, which excludes the reference cell; `e(b_es_*)` has no reference entry; the plots, the saved plot data and the adversarial line plant a zero at the reference relative year; the only margins sites that include `_t==0` are the `contrast(overjoint)` joint-test calls. The non-zero reference margin is nevertheless the symptom of two distinct defects, and the issue is NOT confined to the joint tests: for one mechanism the printed rows are wrong by a constant, for the other every reported row is a parameterisation artifact.

**When it comes up.** Under `interactivecontrols()` the reference-cell margin equals `-s000 x E_w[demeaned covariate | treated reference rows]`, where `s000` is the coefficient on the reference-cell slope column `0._i#0._t#0.targetflag#c.x_dm` that the cell interaction at ado ~1228 creates (`i.targetflag` includes its base level). It is non-zero exactly when that weighted mean is non-zero: a covariate that varies within cohort over time, weights, or an unbalanced panel, under the pooled reference (esfixedbaseperiod shrinks it to one period's mean: 0.024 vs 0.207 on the flagship). It is exactly zero for a time-invariant covariate on a balanced unweighted panel - where the margins column still reads `0bn.` with b = 0, so the `0bn.`/`0bno.` name is not a usable detector; the value is. Under `lattice()` with `contreatcontrols(basic)` it equals the baseline dose slope, always: the guard at ado ~1283 (`... & "latticepart2hash" == ""`) skips the ringer initialisation whenever a lattice is present and nothing else inserts a dose control, so plain `basic` with a lattice inserts NO baseline dose control on the default path (the author's own comment at ~1280 says it should).

**Mechanism 1 - `interactivecontrols()`, binary DiD.
