# F012 - does the unscreened contreat() subgroup path need the wooldid_fcdeg screen?

Research item from the 2026-09-05 quality review (s2, "Not fixed, by design of this
review"), ruled by the author on 2026-09-06: **MORE RESEARCH: construct the
ame-singular / att-healthy case first.** Assessment only; nothing in the package is
changed by this record.

## 1. The question as ruled

The help now says (`wooldid.sthlp` ~358) that wooldid "screens each binary-treatment
subgroup {it:margins} call after the fact (the continuous-treatment subgroup reads under
{cmd:contreat()} are not screened; see the design record)". The review found the same:
the nine `dydx(contreat)` subgroup `margins` calls in the worker (`wooldid.ado` 3498,
3517, 3544, 3608, 3621, 3652, 3683, 3691, 3729) carry no `wooldid_fcdeg` call, while the
binary twins at 3091, 3300, 3318, 3361 and 3416 do.

The author's brief: build the case where the **ame** subgroup `margins` VCE is numerically
singular while the **att** subgroup reads are healthy - the only configuration in which
the unscreened path is actually exposed, because the screen's fallback is global and the
att block runs first - and show whether the unscreened path can then report a
cancellation-residue subgroup ame under the cell collapse.

## 2. Why the att block running first matters (code reading, not measurement)

`wooldid_fcdeg` sets `fcrerun 1`; the call site then does `restore, preserve`, clears
`fcnoes` and sets `fcsg 0`, so **every** later margins call in the worker - including all
nine ame subgroup calls - runs on the full data. The att subgroup block occupies
`wooldid.ado` 3021-3492 and the ame block 3494-3742, both inside the same
`if "\`subgroups'" != ""`. So:

* any run whose att subgroup calls trip the screen has its ame subgroup calls evaluated
  on full data too (protection by accident, but real protection);
* the ame block is exposed only when every att call passes **and** an ame call is in a
  singular direction. That is exactly the "ame-singular / att-healthy" case.

Two further code facts narrow the exposure, both verified by reading the ame block:

* the ame block contains **no** `o.`-marker read at all (`grep` for `o.` / `sgdrop` /
  `strmatch` over 3494-3742 returns nothing; the binary block's SI-7 horizon-drop scan
  sits at 3128-3155). So of the three marker reads the help lists - horizon drop with a
  caution, adversarial-test skip, subgroup joint tests - the ame family only has the
  third, through `wooldid_sgchain` (which skips a posted level whose name carries `o.`)
  and the `test` rank guard at 3670-3682.
* **AMESE R1/R3 (`amescrub`, `wooldid_amescreen , mode(detect)`, `wooldid.ado`
  1599-1612)** blanks the se/t/p/ci of every ame-family capture and disables the ame
  subgroup joint tests whenever any treated `i`-by-`t` cell lies wholly inside one
  cluster. That is precisely the configuration class - clustering at or above the cohort
  variable - that produced all four collapse-induced flips in the 2026-09-01 binary
  assessment (`cell_collapse_subgroups_2026-09-01.md` s2). Measured below (f5).

**Provenance.** Both builds derive from the working-tree `wooldid.ado` as it stood at about
14:02 on 2026-09-06; each run `do`s the ado once at its start, so both arms of a fixture
always share one in-memory build, and the probe and plain builds are bitwise equivalent on
the six fixtures they share (s5). Commit `bd8ee3c` (the F034 bootstrap fixed-metric rank
test) landed at 14:04 during the session; every one of its hunks sits at line 6492 or
beyond, so neither the subgroup margins block (3021-3742) nor `wooldid_fcdeg` /
`wooldid_fcdegx` is affected, and the findings carry to that commit and to the working tree
above it.

## 3. Method

Individual-level synthetic panels built in `lib.do` (`mkfix`): 12 states x 6 years x 10
individuals = 720 rows, 72 `(i, t, targetflag)` cells, so the collapse does real work
(`e(wdid_fcncell) = 72`, `e(wdid_fcol) = 1`). States 1-4 are subgroup 1, 5-8 subgroup 2,
9-12 never treated; onsets at t=3 (states 1,2,5,6) and t=5 (states 3,4,7,8), so the two
subgroups have identical cohort profiles. Dose is a unit-level attribute, drawn on
disjoint ranges by subgroup (sg1 in [1,2), sg2 in [3,4)) so the att contrast between the
subgroups is genuinely non-zero; `y = 2*state + 0.5*year + post*(0.5 + 0.3*dose) + N(0,.4)`.

Every fixture is run twice on identical data - arm **C** (default, collapse engaged) and
arm **U** (`fullprecisionslow`) - with
`wooldid y st yr ttre, att att_it contreat(dose) contreatcontrols(basic) subgroups(sg)
esprelength(2) espostlength(2) jointtests <vce>`. All of `e()` (scalars, macros,
matrices up to 800 cells) is dumped in `%21x` by `dumpe` and compared bit-for-bit by
`diff.py`, with the expected-different keys (`e(wdid_fcol)`, `e(wdid_fcncell)`,
`e(cmdline)`) excluded and numeric-looking macros compared numerically.

Ten fixtures (the brief's cap was eight; two more were added once the probe build below
proved inert), covering the three shapes the brief named plus seven more chosen after the
code reading above:

| id | pathology | vce |
|---|---|---|
| f1 `base` | healthy control | `robust` |
| f2 `constdose` | sg2's dose constant within the subgroup (collinear with its cohort-by-period terms) | `robust` |
| f3 `timedose` | sg2's dose a perfect linear function of time | `robust` |
| f4 `onecell` | sg2's treated cells hold a single observation each (saturated, zero residual) | `robust` |
| f5 `base` | cluster at the cohort variable (the 09-01 flip recipe) | `cluster(st) safety(off)` |
| f6 `base` | 10 clusters, each splitting every treated cell (no cell containment) | `cluster(pidc)` |
| f7 `base` | 4 clusters, each splitting every treated cell (VCE rank <= 4) | `cluster(fourclus)` |
| f8 `constdose` | f2's dose degeneracy under f7's rank-deficient VCE | `cluster(fourclus)` |
| f9 `bothconst` | the dose constant within **both** subgroups (every dose slope dropped) | `robust` |
| f10 `oneunit` | subgroup 2 reduced to a single treated unit | `robust` |

f1-f8 were run under the working-tree ado (`r1_battery.do`); f1, f2, f5, f6, f7, f9 and f10
were run again under an instrumented scratch copy (`r2_probe.do`, s5), whose e() output is
**bitwise identical** to the plain build's on all six fixtures common to the two runs
(`diff.py`: 0 hard diffs, 0 sub-tolerance diffs, both arms).

## 4. Results

### 4.1 Structural bit-for-bit comparison, all ten fixtures

`e(wdid_fcguard)` is empty in arm C on **nine of ten** fixtures - the att screen never
fired, so the ame calls really did run on the collapsed rows unscreened. The exception is
f5.

| fixture | arm-C `e(wdid_fcguard)` | hard diffs C vs U | largest sub-tolerance relative move |
|---|---|---|---|
| f1 base robust | (empty) | 0 | 7.5e-13 (426 cells moved) |
| f2 constdose | (empty) | 0 | 4.1e-13 (326 cells) |
| f3 timedose | (empty) | 0 | 1.7e-13 (316 cells) |
| f4 onecell | (empty) | 0 | 6.2e-13 (287 cells) |
| f5 cluster(i) | **caution** | **20** (all att-family; see 4.3) | 7.5e-13 (325 cells) |
| f6 cluster(pid) | (empty) | 0 | 7.5e-13 (428 cells) |
| f7 cluster(4) | (empty) | 0 | 7.5e-13 (432 cells) |
| f8 constdose+cluster(4) | (empty) | 0 | 3.7e-13 (324 cells) |
| f9 bothconst | (empty) | 0 | 2.4e-13 (146 cells) |
| f10 oneunit | (empty) | 0 | 2.4e-13 (369 cells) |

No ame quantity - level, pairwise contrast, subgroup joint p, event-study horizon,
`e(b_es_ame*)` - differed between the arms on any fixture, at any tolerance above 7.5e-13
relative, and no ame cell changed between present and missing.

The brief named `e(cfx*)` as well; it is out of scope by construction. The cfx matrices are
produced only under `makecfxplots` / `cfxlattice()`, both of which are in `fcbad`
(`wooldid.ado` 5071), so the collapse never engages on a run that computes one and no cfx
cell is ever evaluated on collapsed rows.

f9 is the strongest form of the ame degeneracy available on this shape: with the dose
constant inside both subgroups every treated cohort-by-period dose slope is dropped, so all
four ame rows of `e(pwsgs)` are missing and both ame subgroup joint tests are absent - in
**both** arms - while the att rows are healthy and identical to the last bit.

### 4.2 The ame-singular / att-healthy case DOES exist (f2, f3, f4, f8, f9) - and is inert

f2 (`constdose`) is the case the brief asked for, and it is easy to build. sg2's dose is
constant within the subgroup, so every one of its cohort-by-period dose-slope terms is
dropped for multicollinearity, and the reported ame for that subgroup is an exact zero
with no standard error, while its att rows are fully healthy:

```
e(wdidsgresults_2)      collapsed (C)                            full data (U)
sg2 ame  (b, se, p)     0            .            .              0            .            .
sg2 att  (b, se, p)     1.494636132527205          1.4946361325272086
                        0.10227905349365049        0.10227905349365049
                        5.205451913215327e-42      5.205451913213393e-42
e(wdid_fcguard)         (empty - the att screen never fired)
```

(the att p differs in its 13th significant digit - a 3.7e-13 relative move, in the same
class as the 4.1e-13 maximum over all 326 moved cells on this fixture)

wooldid already tells the user: "Caution: a treatment period coefficient interacted with
something ... was dropped for multicollinearity" and "Caution: standard errors were not
identified for 10 of 70 reported estimates". f3 and f4 reproduce the same shape.

The two arms agree bitwise on that structural zero, and this is not luck: the collapse
does not change the regression (it is fitted on the full data in both arms and only the
`margins` calls see collapsed rows), so a coefficient dropped for collinearity is dropped
identically in both arms and the margin is a sum of exact zeros - there is no residue for
the summation order to move. The pairwise ame contrast in f2 is therefore not degenerate
either (`b = -0.4867, se = 0.2278, p = 0.033`, identical in both arms): sg1 supplies all
of its variance.

Every flipped cell is an att-family cell with `se = 9.31e-10 = 2^-30` - the one-ULP
residue signature of the 09-01 report. Every ame-family cell is missing in **both** arms,
and the ame subgroup joint tests do not exist in either arm, because `amescrub` fired:
"Caution: with standard errors clustered on st, 36 treated i-t cell(s) lie completely
within a single cluster, preventing valid analytic estimation of SEs for AME estimates".

And arm C printed "Caution: wooldid found subgroup contrasts with zero variance at a
subgroup margins call" with `e(wdid_fcguard) = caution` - i.e. the existing screen fired
on the att call. `safety(off)` was needed to reach this state at all (`jointtests` with
clustering at or above `i` is otherwise refused); under the default safety the screen
would have restored the full data at that point and every subsequent ame call would have
run uncollapsed.

### 4.4 What this says about the exposure

The unscreened ame path is exposed only in the intersection of three conditions:

1. no cluster contains a whole treated `i`-by-`t` cell (otherwise `amescrub` blanks the
   ame se/t/p/ci and drops the ame subgroup joint tests, so there is nothing left to
   flip); **and**
2. every att subgroup call passes `wooldid_fcdeg` (otherwise the global fallback protects
   the ame block); **and**
3. an ame subgroup margin, contrast, or pairwise variance is nonetheless a cancellation
   residue rather than an exact structural zero.

Conditions 1 and 3 pull against each other in every mechanism found so far. Under an
unclustered/robust VCE, a saturated design forces the per-cell score to vanish only in the
*clustered* sum; the observation-level sandwich `sum u_i^2 x_i x_i'` has no such
cancellation, so the ame directions are generically non-degenerate (f1, f4, f6, f7). What
does degenerate the ame under robust is collinearity in the *regression* (f2, f3), and
that produces exact zeros that both arms compute identically. Cell containment (f5) gives
the residue, but `amescrub` has already withheld the affected numbers.

## 5. Would the screen have fired on the ame calls? (direct measurement)

A scratch copy of the working-tree ado (`wooldid_probe.ado`) carries five `wdrdump` calls
that write `r(b)`, its column names, `r(V)` and `r(V_vs)` in `%21x` immediately after four
ame subgroup `margins` calls (3498 post levels, 3517 pre levels, 3544 per-subgroup event
study, 3652 post `pwcompare`) and after the binary `pwcompare` pass (3361). The package is
not touched, and the copy is **bitwise inert**: its `e()` matches the plain build's exactly
on all six fixtures rerun under it, in both arms.

`pred.py` re-implements `wooldid_fcdegx` offline on those dumps, once with the current
`j0 = floor(K/2)+1` convention (the binary geometry) and once with `j0 = 1` (the ame
geometry the review proposes); the event-study calls are evaluated with the `levels` flag
the binary twin passes at 3091, which skips the adjacent-difference contrast branch. The
geometry claim is now measured rather than inferred:
the ame subgroup calls return **k = 2** columns (one per realized subgroup, no omitted
`0.targetflag` half) where the binary `pwcompare` pass returns **k = 4**, so `j0` would
indeed have to be 1 for the ame calls and stays 3 for the binary ones.

Verdict of the `j0 = 1` predicate on each ame call, tolerance 1e-9, both arms:

| fixture | ame post levels / pre levels / pwcompare | ame per-sg event study | binary pwcompare (j0 = 3) |
|---|---|---|---|
| f1 base robust | clean | clean | clean |
| f2 constdose | **level variance below tol** | **zero variance** (sg2) | clean |
| f6 cluster(pid) | clean | clean | clean |
| f7 cluster(4) | clean | clean | clean |
| f5 cluster(i) | **contrasts with zero variance** | clean | **contrasts with zero variance** |
| f9 bothconst | **zero variance** | **zero variance** (both sgs) | clean |
| f10 oneunit | clean | clean | clean |

Three findings:

1. **The ame-singular / att-healthy case reaches the predicate.** On f2 and f9 a `j0 = 1`
   screen would fire on every ame subgroup call while the binary `pwcompare` pass is clean -
   so the exposure the review identified is real at the level of the predicate, not only in
   principle.
2. **It never changes an answer.** On every call of every fixture the verdict is identical
   in the collapsed and the full-data arm, and the underlying objects agree to rounding: the
   largest relative movement of any `r(V)` element between the arms is 3.6e-15 and of any
   `r(b)` element 2.4e-15. So the screen would fire, restore the full data, re-issue the call
   and get back the same numbers.
3. **On f5 the binary call fires too**, and it is issued first, which is why the observed run
   printed the caution and set `e(wdid_fcguard) = caution` - the ame calls were already
   protected.

## 6. Conclusion

**The case exists, the predicate would fire on it, and it is inert.** Datasets whose
contreat subgroup ame is singular while the att subgroup reads are healthy are easy to
build - f2, f3, f4, f8 and f9 are five of them - and on all of them the att screen never
fires, so the ame reads really do run on the collapsed rows unscreened. The `j0 = 1`
predicate the review proposes would have fired on every ame subgroup call of f2 and f9
while the binary pass stayed clean (s5), so the gap is real at the level of the screen.

But it does not produce a wrong number. On none of the ten fixtures did any ame quantity
differ between the collapsed and the full-data arm by more than 7.5e-13 relative; no ame
cell moved between present and missing; and at the level of the `margins` return itself the
two arms' `r(b)` and `r(V)` for the ame subgroup calls agree to 2.4e-15 and 3.6e-15, with
the predicate returning the same verdict on both. The reason is structural rather than
lucky: the singularity that is easy to reach on the ame side comes from the *regression*
(a dose slope dropped for collinearity), which both arms compute as an exact zero because
the regression is fitted on the full data in either case - there is no residue for the
summation order to move; while the singularity that does produce a movable residue is cell
containment, and there AMESE R1/R3 (`amescrub`) has already withheld every ame standard
error, p-value and subgroup joint test, so no reported ame number survives for the collapse
to move. The one fixture that did flip (f5) flipped att-family cells only, and the existing
screen fired on it - which, because the att block precedes the ame block and the fallback is
global, would also have pushed the ame calls onto the full data under default safety.

I could not construct the "unscreened ame path returns a wrong number" case in ten fixtures.
This is a negative result, not a proof of impossibility. The search covered a robust VCE,
three clustered VCEs (cell-containing, cell-splitting with 10 clusters, cell-splitting with
4), five degeneracy mechanisms (constant dose in one subgroup, constant dose in both, dose
linear in time, one observation per treated cell, one treated unit per subgroup) and one
balanced individual-level panel shape. What it did **not** cover, and the author should
weigh: (a) every fixture realizes exactly **two** subgroups, so the adjacent-difference
contrast VCE is 1x1 and the predicate's "singular contrast direction" branch cannot be
distinguished from its "contrasts with zero variance" branch - three or more subgroups is
where those separate; (b) all runs are **unweighted**, so no `aweight`/`pweight` summation
path was exercised; (c) on this balanced design `att_it` coincides with `att` to the last
bit in every table, so the cell-weighted estimands exercised no summation the
observation-weighted ones did not; and (d) no row-permutation control was run, because the
09-01 control exists to adjudicate an observed flip and no ame flip occurred to adjudicate.
None of these disturbs the mechanism argument, which is independent of subgroup count and
weighting: a collinearity drop is an exact zero in both arms whatever the weights, and cell
containment blanks the ame cells whatever the subgroup count.

## 7. Recommendation for the author to rule on

**Do not add the screen to the contreat subgroup calls.** Keep the help sentence as it now
stands (it already names the exception), and treat this record as the design record it
points to. Reasons, in order of weight:

1. No measured defect. Ten fixtures, thirty wooldid runs across two builds, zero ame
   differences above 7.5e-13, and identical predicate verdicts in both arms on every
   instrumented call.
2. The regime that makes the residue movable is exactly the regime `amescrub` already
   blanks, so the screen would have nothing to protect there.
3. The att block runs first and its fallback is global, so any run whose att calls are
   degenerate already has its ame calls evaluated on the full data.
4. The ame block reads the `o.` marker in only one place (`wooldid_sgchain`), against the
   binary block's three, so the "changes what is reported" surface is smaller.
5. Where it fires, it costs the speedup for nothing. The predicate is clean on every
   healthy fixture (f1, f6, f7, f10); it fires on a subgroup whose dose slopes were dropped
   for collinearity - a data pathology wooldid already flags with two cautions - and under
   the default safety it would then re-issue that call and every remaining subgroup call on
   the full data, for numbers measured here to be identical. f2 and f9 are exactly that case.
6. The pathological-data effort cap: the fix is not free. `wooldid_fcdegx` needs a `j0`
   flag - `j0 = 1` for the `dydx(contreat)` geometry, now measured (the ame subgroup calls
   return k = 2 columns against the binary pass's k = 4) - plus nine call sites. One of them
   (3691, the pre-period `pwcompare` pass) is `capture`-wrapped and its `_rc` is read on the
   next line, so a screen call cannot simply follow it; two (3652 and 3691) are posted and
   need the un-post / `est restore` dance the binary twin at 3361-3366 carries; and 3608 /
   3621 are the `joint` variant whose `r(p)` guard the binary twin passes explicitly.

If the author wants the gap closed for consistency rather than for a measured defect, the
honest price is the full screen: a `j0` flag on the Mata predicate plus nine call sites, one
of them `capture`-wrapped and two posted. A detection-only half-measure is not recommended:
it would invert the ruled semantics, under which the default safety falls back and only
`safety(off)` proceeds with a caution.
