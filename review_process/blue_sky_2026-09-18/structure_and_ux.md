## Coordinator-verified findings

Four claims I checked myself rather than taking from an agent:


1. **README:141 / sthlp:164 promise a normalized zero that does not exist.** Both state: "Event study
   estimates derived from this approach always have a normalized effect of 0 in the earliest period
   reported (the pooled reference period)." MEASURED on the pinned build, pooled default,
   `esprelength(3) espostlength(3)`: the reported rows are `ES_att_pre3 = -0.143114`,
   `ES_att_pre2 = -0.043947`, `ES_att_pre1 = 0.187458`. All three are estimates; there is no
   normalized-zero row in `e(b)` and the pooled reference gets no row at all. Repro:
   `bluesky/coord/normzero/nz.do`. CONSEQUENCE: a user writes "the earliest pre-period is normalized
   to zero" into a methods section on the strength of README:141, and it is false for their run.
   Two agents converged on this independently; one flagged the plot draws a zero the table has no row for.

2. **The help documents a post-estimation handoff that destroys the user's results.** sthlp:1469:
   "For lincom/test, first repost the event study with `ereturn post e(b_es_type) e(V_es_type)`."
   `ereturn post` REPLACES e() wholesale - so following this instruction discards every other wooldid
   result (the main table, gteffects, the engines' output) with no way back but a re-run. The prose
   says "repost", the command given is `post`.

3. **The .pkg pins a reghdfe version three majors behind what the project baselines on.**
   `wooldid.pkg`: "Requires: STATA 16, reghdfe version 5.7.3"; sthlp:46 repeats it. The project
   develops and baselines on reghdfe 6.12.3, and the ado checks no version of anything. `net describe`
   shows the .pkg text, so this is what a prospective user reads.

4. **The distribution stamp is stale.** `wooldid.pkg`: `Distribution-Date: 20260819`, against a build
   that has changed continuously through 2026-09-16. This is the only field `adoupdate` reads, so
   existing installs are not told there is anything to update. (The author's own next work chunk is to
   bump this - noted here because the specifics are now measured.)
