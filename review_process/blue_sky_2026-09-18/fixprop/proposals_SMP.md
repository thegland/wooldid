## 0. The diagnosis, in one paragraph

Nine findings, one root cause and one aggravating cause.

**Root cause.** `wooldid_bootrun` builds its sample concept at ado:8909-8923 as

```stata
  gen byte `smp' = ((`ifr') == 1)          // user if only
  replace `smp' = 0 if `smp' >= .
  replace `smp' = 0 if missing(`clusv')    // ... plus a non-missing cluster value
```

and nothing else. Every quantity the engine derives from that row set is therefore
derived from the wrong rows: the resampling-cluster count `wdb_C` (ado:8954, which
becomes `bootdf(clusters)`'s *G* via `c_local wdb_r_nclus` at ado:9537), the cluster
row count `n_c` (ado:8941), the nesting-regime predicate (ado:8987-8998), and the frame
the physical re-identification leg draws from (`qui keep if smp`, ado:9345). The
engine's own P7 assertion at ado:9392 already names the three ways rows in that frame
fail to reach a replication ("missing y, an event-study window, singletons") — the
engine knows the frame is not the estimation sample, and then uses it as if it were.

**Aggravating cause.** The nesting predicate at ado:8989-8991 reduces a *per-unit*
property to one global flag by `cap assert`, so one straddling unit out of ninety-six
puts all ninety-six under the keep-i rule that the code's own comment at ado:9331-9334
says "collaps[es] the composition variance of att_i toward zero".

The two are independent and both need fixing: **SMP-1** stops rows the estimator never
sees from deciding anything, **SMP-3** stops one unit deciding for all of them.
**SMP-2** is a small relocation that SMP-1 makes possible. **SMP-4** is the help and
disclosure work, and is the fallback if SMP-3 is declined.

# SMP-1 — make the bootstrap's sample concept the estimation sample

**Findings covered:** FCM-2, FCW-02, HV-BOOT-06, FCM-4, HV-BOOT-04, the cluster-universe
half of HV-BOOT-01 and HV-BOOT-05, and the two REFUTER_FOUND "pre-window cohort" twins.
**Risk: low. Moves reported numbers: YES, but only in a sharply bounded set of runs (measured below).**

## The edit

One insertion in `wooldid_bootrun`, immediately after ado:8923
(`qui replace `smp' = 0 if missing(`clusv')`). Nothing else changes.

```stata
  qui replace `smp' = 0 if missing(`clusv')
+ * SMP-1: the resampling sample concept is the ESTIMATION sample. A row the observed
+ * fit dropped - by wooldid's own deterministic markout (missing y, missing controls,
+ * a missing dose, a zero or missing weight, a unit that never observes its reference
+ * period, a cohort treated before the window opens) or by the estimator (a singleton
+ * fixed-effect group, ppmlhdfe separation) - cannot enter ANY replication: the
+ * replication re-applies the same markout, and on the count leg it never even gets a
+ * weight (`basew' is missing off `smp'). Such a row must therefore not decide the
+ * nesting regime below, must not mint a resampling cluster, and must not set n_c.
+ * The worker builds this marker at ado:1511, before the fastcollapse preserve, and
+ * posts it at ado:4051 after the restore, so it is a marker on the caller's ORIGINAL
+ * rows and is live here: the bootstrap block stores e() but does not clear it.
+ tempvar wdbes
+ cap qui gen byte `wdbes' = e(sample)
+ if _rc != 0 {
+   dis as error "Error: bootstrap() could not read the estimation sample from the observed fit. This is an internal inconsistency - please report it."
+   error 459
+ }
+ qui replace `smp' = 0 if `wdbes' != 1
```

That is the whole fix for seven of the nine findings. The follow-on corrections are
automatic, because every downstream quantity already reads `smp`:

* `wdb_C` (ado:8954) becomes the live resampling-cluster count, so `bootdf(clusters)`
  gives `e(N_clust) - 1` and the `wdb_C < 2` refusal at ado:8956 finally means what its
  message says ("at least 2 clusters **in the estimation sample**");
* the nesting predicate at ado:8989-8991 is computed on the rows the estimator used;
* `qui keep if `smp'` (ado:9345) stops carrying rows into the re-id frame that the
  replication will only drop again;
* `n_c` (ado:8941) is the live row count, which is what `bootalpha(size)` means.

`e(sample)` is a *byte marker on the rows in memory*, so the guard is `!= 1`, not
`== 0`: that also catches a marker that came back missing.

## Cost

Two passes over N: one `gen byte` and one `replace`. No sort, no `gegen`, no frame
work, executed once per run, not per replication. On a 2-million-row panel that is
some tens of milliseconds against a rep loop measured in minutes. It is strictly
*cheaper* downstream: the map frame, the re-id frame copy and every replication's fit
now carry only live rows. On the A5 arm it removed two failed replications out of
sixty (base `e(boot_completed)` = 58, patched = 60) — draws that had been spent on
clusters that could contribute nothing.

## Does it move a reported number?

Yes, and I measured exactly where. `base` = pinned build, `p1` = `b_p1/`, same seed,
same data, `%21x` comparison (`cmp.py r2_base.log r2_p1.log`):

| arm | `se(att_i)` base | `se(att_i)` p1 | verdict |
|---|---|---|---|
| A4 clean | 0.1038698753 | 0.1038698753 | **bit-identical** |
| A4B clean, bayes(equal) = default | 0.0514033688 | 0.0514033688 | **bit-identical** |
| A4C clean, bayes bootalpha(size) | 0.0084050762 | 0.0084050762 | **bit-identical** |
| A0 dead rows, no phantom | 0.1029999001 | 0.1029999001 | **bit-identical** |
| A2 genuine straddler, all rows live | 0.0914245938 | 0.0914245938 | **bit-identical** |
| A1 phantom straddler | 0.0908285672 | 0.1029999001 | **+13.4%, and now exactly A0** |
| A3 one wholly dead cluster | 0.1093863487 | 0.0951847204 | moves; `e(boot_df)` 23 -> 22 |
| A5 12 frame clusters / 8 live | 0.2110655359 | 0.2411305494 | moves; `e(boot_df)` 11 -> 7 |
| A7 4 pre-window cohorts, **no missing data** | 0.1155387446 | 0.1233880684 | moves; `e(boot_df)` 23 -> 19; **equals the oracle bit for bit** |

Read the rule off that table. The engine's draws depend on the *cluster set*, not on
the rows inside a cluster: `bsample, cluster()` consumes one uniform per drawn cluster
whether the cluster has three rows or three hundred. So

* **if no cluster is wholly outside `e(sample)`, nothing moves at all** — A0 proves it
  on 3 dead rows, A4/A4B/A4C on clean data, A2 on a genuine straddle. This is the
  common case and it needs no re-bless;
* **if the regime was wrong, the number moves to the right one** (A1 becomes
  bit-identical to A0, its own no-phantom twin);
* **if a cluster was wholly dead, the number moves** (A3, A5), because *G* changes and
  with it the entire draw stream. Those two arms also moved because the old runs were
  spending draws on clusters that contribute nothing. Be careful reading the *size* of
  the A3/A5 SE moves: at `reps(60)` the two arms are different draw streams, so the
  8-13% there is confounded with Monte-Carlo noise. What is clean in A3/A5 is the
  degrees of freedom and the failure count, not the magnitude.

**Three re-bless surfaces the author must rule on.**

1. *Clustered runs whose frame holds a wholly-dead cluster.* These move and should.
2. *Every unclustered `bootstrap(standard)` run with any row off `e(sample)`, and the
   `phys` leg.* With no `cluster()` the code sets `clusv = _n` (ado:8918-8921), so
   `wdb_C` is the live **row** count, and removing even one dead row changes *G* and
   therefore the whole `bsample` stream. Bit-identity cannot hold there, and does not:
   **measured** on arm A6 (unclustered, `att`, 3 dead rows), `se(att)` moves
   0.0709020868 -> 0.0771345406, +8.8%. On clean data the unclustered leg is
   bit-identical (arm A6B, 0.0702647325 both). This is a wider re-bless surface than the
   clustered case — any unclustered `bootstrap()` baseline with a missing outcome,
   a missing control, a zero weight, a singleton unit or an always-treated cohort — and
   it is the main re-bless cost of SMP-1. It is also, for what it is worth, the clearest
   case that the current behaviour is wrong: without `cluster()` the engine is today
   resampling rows it will then throw away, so a fraction of every replication's draws
   is spent on nothing.
3. *`bootstrap(bayes)` with `bootalpha(size)` and any dead row inside a **live** cluster.*
   Unmeasured but structurally certain from `wooldid_bootdw` (ado:14271-14313): under
   `size`, `n_c` is both the Gamma shape (`a = N[k]`, ado:14286) and the divisor that
   spreads the drawn mass over the cluster's rows (`P = P :/ N`, ado:14311), so removing
   a dead row changes both the draw stream and every live row's multiplier — the number
   moves even though the cluster set is unchanged. Under the **default** `bootalpha(equal)`
   it is inert (`a = 1`, no divisor), which is why arm A4B is bit-identical and why an
   A0-shaped panel under `equal` would be too. Arm A4C only tested `size` on clean data,
   where `n_c` does not change; the `size`-plus-dead-rows cell was not run then.
   **MEASURED SINCE, and it is as predicted** — a second agent re-ran this on an
   independent fixture (section 8, arms D3/D4): `bootalpha(size)` with dead rows inside
   a *live* cluster moves `se(att)` .02511654 -> .02560126 (+1.9%), while
   `bootalpha(equal)` on the identical data is unchanged to every printed digit
   (.1248307 both). **One refinement to "`equal` is inert", though:** inert means
   *partial* death under `equal`. A **wholly dead cluster** moves the number under
   `equal` too (arm D1: .12825823 -> .10925338, -14.8%), because the run then draws 23
   Gamma variates per replication instead of 24 — Dirichlet aggregation leaves the live
   masses distributionally identical, but not the same draws. That case is already
   inside re-bless surface 1 below; it is spelled out here so nobody reads "the default
   `bootalpha(equal)` is inert" as covering it.

Nothing about the **point estimates** moves anywhere: `b(att)` and `b(att_i)` are
bit-identical in every arm of every build. Only the bootstrap covariance and what is
computed from it move.

## Blast radius

* `wooldid_bootrun` only. `wooldid_permrun` (ado:7488) has the same shape and is
  **deliberately excluded**: sthlp:431 documents the permutation *design* sample as the
  if-sample ("rows wooldid later removes by its deterministic markout ... still count
  toward the design"), which is a documented design choice and a separate ruling. If
  the author wants them aligned, that is a second, documented change, not this one.
* `bootsave()` files: `wdb_nrows` (ado:8938) is the live row count, so the `_rep = 0`
  observed row's `1/N` scale under `bootalpha(size)` becomes `1/N_live`. That is the
  BS-18 convention applied to the right N; it only shows in a `bootalpha(size)` +
  weighted `bootsave()` file.
* `bootdisplay(bca)`: the jackknife loop at ado:9490-9493 runs `wdb_C` delete-one-cluster
  fits, so a dead cluster stops costing a wasted fit. Faster, and the acceleration is
  now computed over live clusters only — which is what a delete-one-cluster jackknife
  means.
* `e(boot_df)` changes wherever a dead cluster existed. It becomes *consistent with the
  `e(N_clust)` wooldid already prints in its own header*, which is the internal
  contradiction HV-BOOT-01 caught (`N clusters = 16` on one line and `t(19)` 42 lines
  later).

## The alternative I rejected

**Restrict to `ifvar` (wooldid's internal deterministic screen) rather than
`e(sample)`.** `e(sample)` = `ifvar` minus the estimator's own drops (singleton FE
groups, ppmlhdfe separation). Those drops are *resample-dependent*: a unit that is a
singleton in the observed sample can stop being one in a replication where, under the
keep-i rule, a twice-drawn cluster merges its copies. Restricting to `ifvar` would keep
that row resurrectable. I rejected it for three reasons: (a) `ifvar` is a tempvar of
`wooldid_worker` and is gone by the time `wooldid_bootrun` runs, so it would need to be
plumbed out or re-derived — a much larger edit for a marginal case; (b) HV-BOOT-04 is
*specifically* about the singleton trigger, and `ifvar` does not fix it; (c) the pairs
bootstrap is the sampling distribution of an estimator computed **on `e(sample)`**, and
resampling `e(sample)` is the ordinary reading — it is what `vce(bootstrap)` does
inside a Stata estimation command. Honest statement of the cost: on the keep-i regime,
a singleton row that could have been rescued by a duplicate draw is now never rescued.
I consider that the right trade; the author may not.

**Recompute the predicate in `wooldid_bootctl` instead.** Impossible: `bootctl` is
called from `wooldid_validate` (ado:4941), which runs *before* estimation, so `e(sample)`
there belongs to whatever command ran last. That is also why SMP-2 exists.

## The test that proves it

Three invariants, no oracle needed.

1. **Phantom invariance (metamorphic).** Two datasets that differ only on rows outside
   `e(sample)` must produce bit-identical bootstrap output. Arms A0/A1: assert
   `%21x` equality of the whole `e(V)` diagonal, of `e(N)`, `e(N_clust)`, `e(boot_df)`
   and `e(boot_completed)`. **Measured, passes under `b_p1/`, fails under the pinned
   build** (`se(att_i)` 0.0908285672 vs 0.1029999001).
   Variants that must also pass, each a different door into the same bug: the second
   cluster code on a row with a missing `controls()` variable; on a row with weight 0;
   on a singleton unit's only row (HV-BOOT-04); on a cohort treated before the window
   opens (the REFUTER_FOUND twins, which need no missing data at all).
2. **df consistency (closed form).** On any run with `cluster()` and
   `bootdf(clusters)`, assert `e(boot_df) == e(N_clust) - 1`. **Measured, passes under
   `b_p1/` on A3 (22 = 23 - 1) and A5 (7 = 8 - 1), fails under the pinned build**
   (23 and 11).
3. **Clean-data invariance (regression guard).** On data where `e(sample)` is every
   row, the patched build must be bit-identical to the pinned one. **Measured, passes**
   (A4 / A4B / A4C, standard and both `bootalpha()` flavours).
4. **THE ORACLE IDENTITY — the strongest test, and it passes exactly.** Take a panel
   containing rows the estimator drops, and build the oracle by *physically deleting*
   those rows. The patched build run on the full panel must equal the oracle run,
   bit for bit. Arm A7 is this test on the most realistic trigger there is — four of
   twenty-four industries treated before the estimation window opens, **no missing data
   anywhere in the panel** (the REFUTER_FOUND twins, mechanisms.md:177,183):

   | | `e(boot_df)` | `se(att)` | `se(att_i)` |
   |---|---|---|---|
   | pinned build, full panel | 23 | 0.1223999063 | 0.1155387446 |
   | `b_p1/`, full panel | **19** | **0.1305544540** | **0.1233880684** |
   | oracle (rows deleted), either build | **19** | **0.1305544540** | **0.1233880684** |

   Every digit of the patched full-panel run matches the oracle, for both estimands and
   for the degrees of freedom; the point estimates are bit-identical in all three. The
   pinned build's standard errors are 6.3% and 6.4% *below* the oracle, and its `t(23)`
   should be `t(19)`. This one has **no Monte-Carlo caveat at all** — it is an exact
   identity, and it is the test I would put in the suite.

# SMP-2 — move the two few-cluster cautions to where the live cluster count exists

**Findings covered:** the guard-suppression half of HV-BOOT-01 and HV-BOOT-05.
**Risk: low. Moves reported numbers: NO** (it only adds text to the output).

## Why SMP-1 alone is not enough

SMP-1 fixes `e(boot_df)`, but the two cautions live in `wooldid_bootctl`
(ado:6486-6497), which is called from `wooldid_validate` at ado:4941 — *before the
estimation runs*. `e(sample)` does not exist there, so `smp2` (ado:6459-6463) cannot be
corrected in place. I confirmed this on the A5 arm: under `b_p1/` the degrees of freedom
are right (7) but **neither caution prints**, exactly as in the pinned build.

HV-BOOT-05's worst case is the reason this matters: 12 clusters in the frame, 2 in
`e(sample)`. SMP-1 alone gives `t(1)` instead of `t(11)` — the 5.8x interval-width fix —
but the run still says nothing about being a two-cluster bootstrap.

## The edit

**(a)** In `wooldid_bootctl`, delete the `< 10` caution and the whole `F050` treated-cluster
block (ado:6486 and ado:6489-6497), keeping the `r(max) < 2` refusal above them and the
reps-resolution cautions untouched. sthlp pins only the *refusal* to parse time ("That
one fires when the options are screened, before the estimation runs"); it says nothing
about when the cautions fire, so this is help-neutral.

**(b)** In `wooldid_bootrun`, immediately after the `wdb_C < 2` refusal (ado:8956-8959),
with `smp` already corrected by SMP-1:

```stata
+ * SMP-2: the few-cluster cautions, on the LIVE resampling-cluster count. They used to
+ * run in wooldid_bootctl at parse time, on the user-if frame, where a cluster
+ * contributing no rows to e(sample) counted toward both thresholds and could suppress
+ * them; e(sample) does not exist that early, so they move here rather than being fixed
+ * in place. The two-cluster REFUSAL stays in bootctl - sthlp documents it as firing
+ * when the options are screened - and the wdb_C < 2 check just above is its live twin.
+ if "`clus'" != "" {
+   if `wdb_C' < 10 dis as text "Caution: only `wdb_C' clusters are available for the bootstrap; bootstrap inference is unreliable with very few clusters."
+   if "`ttrevar'" != "" {
+     tempvar wdbtrt wdbctr wdbctag
+     qui gen byte `wdbtrt' = (`ttrevar' < .) if `smp'
+     qui gegen byte `wdbctr' = max(`wdbtrt') if `smp', by(`clusv')
+     qui gegen byte `wdbctag' = tag(`clusv') if `smp' & `wdbctr' == 1
+     qui count if `wdbctag' == 1
+     if r(N) < 6 dis as text "Caution: only " r(N) " treated cluster(s) are available for resampling. ... <the existing F050 message verbatim, with cond("`mode'" == "bayes", ...) in place of cond("`bootstrap'" == "bayes", ...)> ..."
+     drop `wdbtrt' `wdbctr' `wdbctag'
+   }
+ }
```

The message text is moved verbatim. Only the mode test changes name: in `bootrun` the
local is `mode`, not `bootstrap`.

## Cost

Net **zero**: the same one `gegen max`, one `gegen tag` and one `count` that `bootctl`
runs today, run once, in the other program. `bootctl` loses a `gegen group` of its own
(`cgrp` is still needed for the refusal, so that one stays). One `gegen` is cheaper
than it was, because `smp` is now the smaller row set.

## Blast radius

Output text only, and its position: the cautions now print just above the
`Bootstrap replications (N):` dots line instead of during option screening. They print
on strictly more runs than before (never fewer: a live cluster is always a frame
cluster). Any test that greps the log for these strings by position will need
re-pointing; any test that counts cautions on a dead-cluster fixture will see one or
two more.

## The alternative I rejected

**Leave them in `bootctl` and pass the live count down from the worker.** The worker
would have to compute a live cluster count and `c_local` it into `validate`'s scope
across a program boundary that does not exist today; and `bootctl` is called
*unconditionally* (including on runs with no `bootstrap()` at all) for its
stray-companion screen, so the plumbing would run on every wooldid call. Rejected as
more code, more coupling and more cost for the same text.

**Re-check in the shell's bootstrap block after `qui wooldid_validate`.** `e(sample)` is
live there, but the block would then have to rebuild the cluster universe a third time.
`wooldid_bootrun` already has it in `wdb_C`.

## The test that proves it

An **oracle-free A/B**: take any panel, pick a cluster, and set its outcome to missing.
Assert that the run prints the same caution set as the run on the same panel with those
rows *physically dropped*. Under the pinned build the two differ; under SMP-1+SMP-2 they
must not. Arm A5 is that test at the threshold: 12 frame clusters, 8 live, 4 live
treated — both cautions must fire, and under the pinned build and under `b_p1/` neither
does. Second assertion, HV-BOOT-01's internal contradiction: the caution's count and
the `N clusters =` figure in the header must be the same number.

# SMP-3 — make the nesting rule per-unit, because nesting is a per-unit property

**Findings covered:** FCM-1, FCW-01.
**Risk: medium. Moves reported numbers: YES, on any `bootstrap(standard)` +
cell-weighted-estimand run whose `cluster()` nests *some but not all* of its `i` values.**

## Why SMP-1 does not cover this

SMP-1 removes the *phantom* straddler — a straddle visible only on rows the estimator
threw away. A **genuine** straddle, inside `e(sample)`, still flips all ninety-six units
to keep-i. Measured on arm A2 (firm 1 genuinely recorded under industry 2 from 2005, all
rows live): `se(att_i)` is 0.0914245938 against 0.1038698753 on the otherwise identical
clean panel — a 12.0% fall — and that number is **bit-identical under the pinned build
and under `b_p1/`**, which is the proof that SMP-1 does not touch it. FCW-01's refuter
measured the same effect at 4.5-14% (mean 10%) on realistic input; the prober measured
23% on a low-noise design. All three agree on sign and on the selectivity: `se(att)` is
essentially unmoved (A2: 0.1076934757 vs A4 0.1100174848) and `b(att_i)` is bit-identical.

One reading to head off. HV-BOOT-06's "discriminating control" gives the straddler a real
outcome, so keep-i becomes the regime the shipped rule *intends*, and reports .1019 —
close to the full-data .1018 and far from that probe's oracle .1252. That control proves
the regime flip is the mechanism; it is **not** a licence for the global rule, because
.1019 is still 19% under the oracle. That residual gap is FCM-1/FCW-01, i.e. this
proposal.

The code says why this is wrong, at ado:9334-9337: keeping `i` under nesting "would make
a twice-drawn cluster's cells identical duplicates that the equal-cell weighting counts
ONCE, collapsing the composition variance of att_i toward zero". With one straddler out
of ninety-six, ninety-five units are in exactly that position.

## The edit

Two hunks in `wooldid_bootrun`.

**(a) the predicate,** replacing ado:8987-8998:

```stata
  local wdb_nest 0
  local wdb_nstrad 0
  local wdb_ioff 0
  tempvar wdbunest
  if "`reid'" != "" & "`clus'" != "" {
    * SMP-3: nesting is a property of a UNIT, not of the run. `wdbunest' is 1 on the
    * rows of a unit that lies wholly inside one cluster and 0 on a straddler's rows;
    * the leg below gives the first a fresh code per drawn copy and keeps i on the
    * second. `wdb_nest' now means "at least one unit is re-identified", which is what
    * the caller's A10 caution is about.
    tempvar wdbcmin wdbcmax wdbstag
    qui gegen double `wdbcmin' = min(`clusv') if `smp', by(`i')
    qui gegen double `wdbcmax' = max(`clusv') if `smp', by(`i')
    qui gen byte `wdbunest' = (`wdbcmin' == `wdbcmax') if `smp'
    qui replace `wdbunest' = 0 if `wdbunest' >= .
    qui gstats sum `wdbunest' if `smp', nod
    local wdb_nest = (r(max) == 1)
    qui gegen byte `wdbstag' = tag(`i') if `smp' & `wdbunest' == 0
    qui count if `wdbstag' == 1
    local wdb_nstrad = r(N)
    * the two code spaces must not collide: a straddler keeps its own i, so the drawn-
    * copy codes are offset past max(i). With no straddler the offset is 0 and the
    * expression below is byte-for-byte today's group(__wdbns, i).
    if `wdb_nstrad' > 0 {
      qui gstats sum `i' if `smp', nod
      local wdb_ioff = r(max)
    }
    drop `wdbcmin' `wdbcmax' `wdbstag'
  }
  c_local wdb_nstrad `wdb_nstrad'
```

**(b) the re-identification,** replacing ado:9349-9350:

```stata
-       if `wdb_nest' qui gegen double __wdbnewi = group(__wdbns `i')
-       else qui gen double __wdbnewi = `i'
+       if `wdb_nest' & `wdb_nstrad' == 0 qui gegen double __wdbnewi = group(__wdbns `i')
+       else if `wdb_nest' {
+         qui gegen double __wdbnewi = group(__wdbns `i') if `wdbunest' == 1
+         qui replace __wdbnewi = `wdb_ioff' + __wdbnewi if `wdbunest' == 1
+         qui replace __wdbnewi = `i' if `wdbunest' != 1
+       }
+       else qui gen double __wdbnewi = `i'
```

The first branch is the *unchanged* all-nesting expression, so the hot path is byte-for-
byte what ships today. The third branch is the unchanged no-nesting expression. Only the
mixed case is new — which is exactly the case both findings are about.

## Cost

Outside the loop, once: one `gen byte`, one `replace`, one `gstats sum`, one `gegen tag`,
one `count`, and on a straddling run one more `gstats sum`. That is about three extra
O(N) gtools passes per run, against a rep loop of hundreds of full `wooldid` fits.

Inside the loop: **nothing at all** on the two pure regimes, because they keep their own
one-statement branch. On a mixed run, two extra `replace` passes over the resampled frame
per replication — call it single-digit percent of a replication whose dominant cost is a
`reghdfe` fit plus `margins`.

One extra byte column (`wdbunest`) rides along in the per-replication `frame copy`, and
only on the reid+cluster leg. On 2 million rows that is 2 MB copied per replication on a
leg that already copies the whole dataset.

## Does it move a reported number?

Yes — and only in the mixed case. By construction:

* all units nest -> first branch -> identical expression, identical output;
* no unit nests -> third branch -> identical expression, identical output;
* mixed -> `se(att_i)`, `se(att_it)`, `se(att_itime)` and everything computed from the
  bootstrap covariance of those estimands **rise**, back toward the value the same data
  would give with the straddler removed. `se(att)` and every point estimate are
  untouched (the stage-1 regression is invariant: FCW-01's `probe1b_mechanism.do`
  isolates this, and my A2 `b(att_i)` is bit-identical across all four builds).

**Measured** (`b_p123/`, arm A2: one genuine straddler out of 96 units, all rows live,
`reps(120) rseed(4242)`):

| quantity | clean panel (A4) | A2 pinned build / `b_p1` / `b_p12` | A2 `b_p123` |
|---|---|---|---|
| `se(att_i)` | 0.1038698753 | 0.0914245938 (88.0% of clean) | **0.1022941175 (98.5% of clean)** |
| `se(att)` | 0.1100174848 | 0.1076934757 | 0.1076934757 (agrees to 1.7e-15, i.e. the last ulp) |
| `b(att_i)` | — | 0.4891035712 | 0.4891035712 (bit-identical) |

So one straddling unit out of ninety-six costs 12.0% of `se(att_i)` under the shipped
rule and 1.5% under the per-unit rule — which is about what one unit out of ninety-six
*should* cost. `se(att)` moves by one ulp, confirming that the stage-1 fits are the same
and only the estimand weights changed. And the bit-identity guards hold: A4, A4B, A4C
and A0 are bit-identical between `b_p12/` and `b_p123/`.

This needs a re-bless of any blessed baseline whose `cluster()` cross-cuts `i` for at
least one unit under `bootstrap(standard)` with a cell-weighted estimand or with
`boottstat`. It is the one proposal here that changes a *method*, and the author must
rule on it.

## Blast radius

* **`gteffects` / `makecfxplots` cell harvesting is safe — checked in code and measured.**
  The reid leg calls `wooldid_bootcells(..., "`wdbrf'", "`i'")` (ado:9432) and the mata
  routine (ado:14783) translates each replication row's `__wdbnewi` back to the original
  `i` *by reading both columns off the replication's own frame* (ado:14800-14810). It
  makes no assumption about how the codes were built, so a mixed code space is fine.
  **Measured** on arm A8 (`gteffects` + a genuine straddler + the reid leg, `reps(40)`):
  `b_p123/` runs clean (`rc = 0`), `e(gteffects)` has the same 224 rows as the pinned
  build, every cell *estimate* is bit-identical, the cell standard errors move in the
  last two or three hex digits only, and `se(att_i)` shows the intended SMP-3 lift
  (0.0998176772 -> 0.1077813470, +8.0%). No key collision, no dropped cell, no caution
  about un-keyable cells.
* **The A10 caution** (shell, ado:~405) keys on `wdb_nest`, whose meaning changes from
  "every unit nests" to "some unit is re-identified" — which is when the caution is true.
* **sthlp:532 must change.** It currently states the rule as a run-level dichotomy
  ("Where the cluster nests i, each drawn copy of a cluster becomes a fresh set of units.
  Where the cluster is finer than i, or cuts across it, the units are kept exactly as they
  are"). Under SMP-3 it is per unit. See SMP-4.
* **Nothing outside the reid leg.** The count leg, the bayes leg and the `phys` leg never
  read `wdbunest`.

## Alternatives I rejected

1. **Reinstate the pre-2026-09-16 `r459` refusal on a straddling cluster.** It is the
   safest thing that is certainly not silently wrong, and it is what the code did until
   three days ago. Rejected because the T2/T3 ruling deliberately removed it on the
   ground that "`i` is an estimand-definition choice and `cluster()` is a claim about
   dependence; a cluster finer than or cross-cutting `i` is a legitimate pairing"
   (ado:6447-6457). I agree with that ruling. What these findings show is that the
   *replacement rule* does not deliver on it — not that the refusal was right.
2. **Keep the global flag but pick the majority rule** (re-identify everyone if most
   units nest). Cheaper, but it is wrong in the other direction for the straddlers: it
   splits them into two units in every replication whether or not anything was
   duplicated, which is precisely the failure the keep-i branch exists to avoid.
3. **Disclosure only** — a caution plus an `e()` marker, no change of rule. This is
   SMP-4; I recommend it *in addition*, and as the fallback if SMP-3 is declined,
   because a silent 10-14% anti-conservative move is the part of FCM-1/FCW-01 that is
   indefensible even if the rule itself is judged a matter of taste.

## The test that proves it

**A closed-form cluster-level design, no oracle.** Make the treatment effect constant
within a cluster and varying across clusters (`tau = f(cluster)`), with negligible noise.
Then `att_i` under a pairs-cluster bootstrap has a known variance: `Var_g(tau)/G` in the
re-identifying regime, and `(1/e)/(1-1/e) = 0.582` of it in the presence-only regime
(FCW-01 measured 0.454 against a predicted 0.454, and 0.348 against a predicted 0.346).
Assert that a panel with *k* straddlers out of *n* sits at the re-identifying value for
small *k* and moves smoothly with *k*, instead of stepping to the presence-only value at
*k = 1*. FCM-1's dose curve (k = 0, 1, 5, 20, flat from k = 1) is the current failure of
exactly that test.

**A cheaper regression guard, which I ran:** `se(att_i)` on a one-straddler panel must be
close to `se(att_i)` on the same panel with that straddle removed, not 12% below it
(A2 vs A4).

**A bit-identity guard:** an all-nesting panel and an all-straddling panel must give
bit-identical output before and after the patch (A4 and, e.g., `cluster()` set finer than
`i` throughout).

# SMP-4 — say which rule was taken (help + two `e()` scalars + one caution)

**Findings covered:** the "silently / no message / no `e()` record" half of FCM-1,
FCW-01, FCW-02 and FCM-2; the documented-vs-actual leg of FCM-2 and FCW-02.
**Risk: none. Moves reported numbers: NO.**

This is the cheapest proposal here and I would ship it whatever happens to SMP-3. Today
a run takes one of two rules that differ by 10-14% in `se(att_i)` and there is no way,
from the output or from `e()`, to tell which.

## The edits

**(a) two `e()` scalars.** `wooldid_bootrun` already `c_local`s `wdb_nest` to the shell;
add `wdb_nstrad` beside it (SMP-3 hunk (a) already does). Post both **from the shell**,
immediately after `wooldid_bootwire` returns (ado:~426): `wooldid` is eclass and has
`wdb_reid`, `wdb_nest`, `wdb_nstrad` and `cluster` all in scope there.
(`wooldid_bootwire` is the wrong home — it has no `reid` local and is not handed
`wdb_nest`/`wdb_nstrad`.)

```stata
+ if "`wdb_reid'" != "" & "`cluster'" != "" {
+   ereturn scalar boot_reid = `wdb_nest'
+   ereturn scalar boot_nstraddle = `wdb_nstrad'
+ }
```

`e(boot_reid)` says whether drawn copies got fresh unit codes; `e(boot_nstraddle)` says
how many `i` values straddle two or more clusters *in the estimation sample*. Together
they let a user, a test or a future reviewer reconstruct which variance was computed.
Without SMP-3, `e(boot_nstraddle) > 0` and `e(boot_reid) == 0` is precisely the
configuration FCM-1 and FCW-01 describe.

**(b) one caution**, printed from `wooldid_bootrun` when `wdb_nstrad > 0`:

*With SMP-3:* "Caution: N of the `i` values in the estimation sample straddle two or
more `cluster()` values. Those units keep their own identity in every replication (a
twice-drawn cluster brings them back as duplicate rows inside the same cell) while the
units that nest inside one cluster are re-identified per drawn copy, so the straddlers
contribute less to the composition variance of the cell-weighted estimands."

*Without SMP-3 (the fallback):* "Caution: N of the `i` values in the estimation sample
straddle two or more `cluster()` values, so every unit keeps its own identity in every
replication. A twice-drawn cluster then contributes its treatment cells once rather than
twice, and the bootstrap standard errors of att_i / att_it / att_itime omit part of the
composition variance and can be too small — measured at 10-14% on panels where only one
unit straddles. `bootstrap()` standard errors for `att` and for the ame family are
unaffected. Consider `egen newi = group(`i' `cluster')`, or a `cluster()` that nests
`i`." This is the same shape as the `bootstrap(bayes)` cell-variance caution already at
ado:6442, which is the project's own precedent for naming an omitted variance component.

**(c) the help.** Three sentences to change, at three located line numbers.

1. The rule is stated as a run-level dichotomy: "Where the cluster nests *i*, each drawn
   copy of a cluster becomes a fresh set of units ... Where the cluster is finer than
   *i*, or cuts across it, the units are kept exactly as they are". Under SMP-3 that
   becomes per unit; **without** SMP-3 it needs the missing sentence: *a single
   straddling unit puts every unit under the second rule.* As it stands this is the
   documented-vs-actual divergence FCM-2 and FCW-02 both cite, and it is the one leg of
   those findings that survives every refuter. **The same dichotomy is stated a second
   time at sthlp:241**, in the "Options that treat the cell-weighted estimands
   differently" paragraph - "Where {it:cluster()} nests {it:i} the copies become distinct
   units; where it is finer than {it:i}, or cuts across it, the copies stay inside their
   cohort" - and needs the same change. Under SMP-1 alone both sentences need the
   qualifier *in the estimation sample*; under SMP-3 both become per-unit statements.
   Fixing only :532 leaves the wrong rule documented at :241.
2. Add, once, that **`bootstrap()` resamples the estimation sample**: rows wooldid
   removes by its markout are not resampled and do not count toward the cluster count.
   sthlp:431 already says the opposite for `permute()`'s design ("rows wooldid later
   removes by its deterministic markout ... still count toward the design"); the
   asymmetry then becomes deliberate and visible rather than an unremarked accident.
3. **sthlp:554**, `bootdf()`: the entry says *G* is "the number of {cmd:cluster()}
   groups". Make it the number of `cluster()` groups **represented in the estimation
   sample**, i.e. `e(N_clust)`. After SMP-1 that is true, and it
   removes the contradiction HV-BOOT-01 found between the header's `N clusters = 16` and
   the same output's `t(19)`.

## Cost, blast radius, test

Two scalars and, on a straddling run, one line of text. No new computation beyond what
SMP-3 hunk (a) already does (and if SMP-3 is declined, one `gegen tag` + `count`, once
per run, to produce the count). Blast radius: any test that diffs the full `e()` scalar
list will see two new entries; any log-diffing test on a straddling fixture sees one new
line. The test is trivial and worth having: assert `e(boot_nstraddle) == 0` on a nesting
panel and `== k` on a panel built with *k* straddlers, and assert the caution fires iff
`e(boot_nstraddle) > 0`.

# 5. What I did NOT test, and what I would want measured before shipping

I patched and ran three builds of the ado (`b_p1/`, `b_p12/`, `b_p123/`) against the
pinned build on one fixture family. That fixture is a clustered, unweighted, linear,
subgroup-free, `bootstrap(standard)` / `bootstrap(bayes)` run on the physical
re-identification leg. Everything outside it is reasoning, not measurement:

* ~~**`boottstat` + `cluster()`**~~ — **GAP CLOSED, see section 8.** It was the
  highest-value one: the studentized path takes the same reid leg and has its own P7
  `e(N_clust)` assertion. Measured on all three builds (arms H/Hn/I/I0): the mixed code
  space does **not** trip the P7 assertion (`rc = 0`, 30/30 replications completed),
  pure-regime runs reproduce to every printed digit before and after both patches, and the phantom
  straddler reaches the boottstat path through the **studentized intervals** rather than
  the standard-error column — which under `boottstat` is the *analytic* SE and is
  therefore regime-invariant by construction, so the defect is invisible in the `se`
  column and visible only in the CI. SMP-1 restores exact identity there. One scope
  correction falls out of this: under `boottstat` the phantom moves **`att`'s** interval
  too, not only the cell-weighted estimands'.
* **`poisson` / ppmlhdfe.** `e(sample)` there excludes separated observations; SMP-1
  would drop them from the resample frame. Mechanically the same argument as singletons,
  but unmeasured.
* **Weighted runs** (`aw`/`pw`). `basew` is already built `if smp` so the algebra is
  unchanged, but `wdb_nrows` (the `bootsave()` observed-row scale) moves under
  `bootalpha(size)` + weights.
* **`subgroups()`**, **`contreat()`/`lattice()`**, **`bootdisplay(bca)`'s jackknife loop**
  (which runs `wdb_C` fits and therefore gets cheaper and, on a dead-cluster frame,
  different), **`bootsave()` file contents** (one fewer column per dead cluster),
  **`simultaneousbands`**.
* **The `e(boot_df)` -> interval-width consequence at HV-BOOT-05's extreme** (12 frame
  clusters, 2 live: t(11) vs t(1), a 5.8x width factor). My A5 arm is the milder
  8-live-cluster version. SMP-1 fixes the df there by construction, but I did not
  reproduce the two-cluster extreme.
* **The size/coverage consequence.** Nobody has measured what the phantom-straddler
  understatement or the wasted-draw inflation does to *coverage*. The project already
  has a finding that `bootstrap(standard)` at `cluster() == i` OVER-covers (.9933 at
  nominal .95, known_bydesign section 7, no ruling). These fixes push in both
  directions — SMP-1 removes an inflation on dead-cluster frames and removes an
  understatement on phantom frames; SMP-3 removes an understatement. A coverage
  simulation on a straddling design, before and after, would be the honest closing
  argument for SMP-3 and I could not run one in the time available.
* **Large-data timing.** I priced the added work by counting passes, not by measuring.
  The claim "three extra O(N) gtools passes per run, none per replication on the
  unchanged regimes" is structural and I stand behind it, but it is not a stopwatch
  number.

One more thing I want to be careful about. FCM-4's and HV-BOOT-01's SE movements
(arms A3 and A5) are **not** cleanly attributable to the fix: removing a dead cluster
changes *G* and therefore the whole `bsample` stream, so at `reps(60)` the 8-13% moves
are confounded with Monte-Carlo noise. What is clean there is `e(boot_df)`, `e(N_clust)`
consistency, the caution set, and the replication failure count (58/60 -> 60/60). If the
author wants the magnitude, it needs a many-seed run.

| arm | data | pinned `se(att)` | buildB | pinned `se(att_i)` | buildB | `e(boot_df)` |
|---|---|---|---|---|---|---|
| A | clean | .1531863 | **.1531863** | .15547203 | **.15547203** | 23 -> 23 |
| B0 | firm 1's `y` missing from t=5 | .15110461 | **.15110461** | .15366729 | **.15366729** | 23 -> 23 |

| C | industry 20 wholly dead, count leg | .15358643 | .13581912 | — | — | 23 -> **22** |
| Cr | industry 20 wholly dead, reid leg | .15358643 | .13581912 | .15581381 | .13712493 | 23 -> **22** |

| D3 | bayes `bootalpha(size)` + dead **rows** only | .02511654 | .02560126 | — | — | 23 -> 23 |
| D4 | bayes `bootalpha(equal)` + dead **rows** only | .1248307 | **.1248307** | — | — | 23 -> 23 |
| E | 12 frame clusters, 8 live, 4 live treated | .14798299 | .14611031 | — | — | 11 -> **7** |
| F | one singleton unit in its own cluster | .13780894 | **.1531863** | — | — | 24 -> **23** |

Four things in that table are worth reading twice.

1. **Arm B is the metamorphic test, and it passes exactly.** B and B0 differ only on
   four rows the estimator never sees. Under the pinned build `se(att_i)` differs by
   **-23.1%**; under `buildB` B reproduces B0 to every printed digit. `se(att)` is
   identical in all four cells, which proves the two arms drew the same clusters.

2. **Arm F is a second exact oracle identity — for the singleton trigger (HV-BOOT-04),
   which section 7 did not have one for.** Arm F is arm A plus one extra row: a unit
   observed once, in its own cluster, with **every variable present and nothing
   missing anywhere**. That row is never in `e(sample)` (reghdfe drops the singleton
   group), `e(N)` is 768 either way and `b(att)` agrees to every printed digit. Yet the pinned build
   reports `se(att) = .13780894` against arm A's `.1531863` — **one irrelevant row moved
   the reported bootstrap standard error by -10.1%** — and `t(24)` where the live count
   is 23. Under `buildB` arm F **is** arm A, to every printed digit, with
   `e(boot_df) = 23`.
   This is the cheapest possible regression test for SMP-1 and I would put it in the
   suite next to section 7's A7: append one singleton row to any panel and assert
   identity at every printed digit.

3. **The bayes cells (D1-D4) settle the open question of section SMP-1.** `bootalpha(size)`
   + dead rows inside a live cluster **does** move (+1.9%), as predicted from `n_c`;
   `bootalpha(equal)` on the identical data does **not** (equal to every printed digit). But
   `bootalpha(equal)` + a **wholly dead cluster** moves (-14.8%), because the Dirichlet
   then has 23 components instead of 24 and the seed stream diverges even though the
   live masses are distributionally identical. "The default is inert" is true only of
   partial death.

4. **The guards come back, and so does the degrees of freedom.** Arm E on the pinned
   build prints `N clusters = 8` in its own header, then `t(11)` forty lines later, and
   **no caution of any kind**. Under `buildB` it prints `t(7)`, `e(boot_df) = 7 =
   e(N_clust) - 1`, and both "only 8 clusters are available" and "only 4 treated
   cluster(s) are available". Across all eleven arms `e(boot_df) == e(N_clust) - 1`
   holds under `buildB` and fails in four of eleven under the pinned build.

## 8.3 Phase 2 — the `boottstat` gap (section 5's "priority check") is closed

Same fixture; `att att_i cluster(ind) bootstrap(standard) boottstat reps(30) rseed(4242)`,
which takes the reid leg through the `boottstat`-plus-`cluster()` route rather than
through the cell-weighted-estimand route.

| arm | data | build | `se_analytic(att_i)` | studentized 95% CI for `att_i` |
|---|---|---|---|---|
| I0 | firm 1's `y` missing from t=5 | pinned | .0822492 | [1.5923502, 2.2639129] |
| I | I0 **and** those dead rows carry `ind == 2` | pinned | .0822492 | **[1.5390551, 2.1728341]** |
| I | same | **buildB** | .0822492 | **[1.5923502, 2.2639129]** = I0 exactly |
| I | same | buildC | .0822492 | [1.5923502, 2.2639129] |

Three results:

* **The phantom is invisible in the `se` column on this path.** Under `boottstat` the
  printed standard error is the *analytic* one (the studentization's denominator), which
  the regime cannot touch; the damage is entirely in the studentized interval, whose
  width falls **5.6%** (0.6716 -> 0.6338). Any test that watches the `se` column would
  have missed this. SMP-1 restores arm I to arm I0 **to every printed digit of both
  endpoints**.
* **`att`'s interval moves too** ([1.6593506, 2.2949786] -> [1.6574511, 2.2978885]), so
  on the `boottstat` path the phantom is not confined to the cell-weighted estimands the
  way it is under plain `bootstrap(standard)`. Worth a sentence wherever the scope of
  these findings is stated.
* **No P7 interaction.** `rc = 0` and 30 of 30 replications completed on every
  `boottstat` arm of `buildC`, including the mixed-code-space one. The assertion at
  ado:9392 counts distinct `__wdbns` — the resampled *cluster* identity — which SMP-3
  never touches, so the concern that flagged this as the priority check does not
  materialise. Arms `Hn`, `I`, `I0` agree to every printed digit between `buildB` and `buildC`.

## 8.4 SMP-3, replicated on a genuine straddler

`bootstrap(standard)`, `reps(60) rseed(4242)`, one genuine straddler (firm 1 recorded
under industry 2 from t=5 on, **all rows live**) out of 96 units.

| arm | build | `se(att)` | `se(att_i)` |
|---|---|---|---|
| Gn clean panel (all 96 nest) | pinned = buildB = buildC | .13604419 | .13403805 |
| Gc same panel, straddling unit deleted (95 units) | pinned = buildB = buildC | .13485673 | .132894 |
| G one genuine straddler | pinned / buildB | .13531408 | **.13018856** |
| G one genuine straddler | **buildC** | .13531408 | **.13352755** |

* The shipped rule costs **2.9%** of `se(att_i)` on this design for one straddling unit
  out of 96 (FCM-1 measured 20-29% on a near-pure-composition design, FCW-01's refuter
  4.5-14% on realistic input, section SMP-3 12.0%; this is a fourth independent
  measurement of the same effect and the range is now 2.9-29%, all in the same
  anti-conservative direction). **The percentage is design-dependent; the direction and
  the silence are not.**
* `buildC` recovers **87%** of the gap to the clean panel and lands essentially on `Gc`,
  the same panel with that unit removed — which is what "one unit out of ninety-six"
  ought to cost.
* `se(att)` reproduces to every printed digit across all three builds in every arm, and
  so does every point estimate: the stage-1 fit is invariant and only the estimand
  weights move.
* **Both no-regression guards hold.** The all-nesting arm (Gn) and the straddler-free arm
  (Gc) are unchanged by SMP-3, on the `bootstrap(standard)` and the `boottstat` path
  alike, because the two pure regimes keep their own unchanged one-statement branch.
* The SMP-4 caution fires and reads: *"Caution: 1 of 96 units straddle more than one
  cluster() group in the estimation sample."*

## 8.5 Implementation notes from re-deriving the patch

* My `buildC` differs from section SMP-3's hunk in one detail and I prefer section
  SMP-3's: it offsets the re-identified codes past `max(i)`, where I re-coded the base
  space with `group(i)`. Offsetting past `max(i)` leaves the kept units' codes *literally
  the original `i`*, which is one less thing that can perturb a fixed-effect ordering.
  Both give a disjoint code space; take the one in SMP-3.
* The `e(sample)` read must sit **above** the rep-0 comparator (ado:~9066). After that
  fit the live `e()` is the comparator's, not the observed run's, and the same
  expression would silently mean something else. Both of us put it at ado:8924; the
  constraint deserves a comment in the shipped code, because the two sites look
  interchangeable and are not.
* `cap gen byte = e(sample)` then `error 459` on failure, never a silent fall-back to
  `smp`: falling back would reinstate the defect on exactly the runs where the read
  failed.
* **Precision caveat, stated plainly.** My `%21x` dump inside a `capture`-wrapped display
  program produced nothing and I did not spend a run diagnosing it, so every figure in
  sections 8.2-8.4 is read off wooldid's own printed table: 7-8 significant digits, i.e.
  a tolerance of about 1e-8, which is *looser* than this project's 1e-10 indifference
  threshold. Where I write "identical to every printed digit" that is what I mean, and it
  is weaker than bit-identity. True bit-identity for the same arm classes is established
  in sections 1-7, whose `cmp.py` compares `%21x` dumps; my fixture corroborates at 8
  digits on independent data and independent seeds. Anyone blessing a baseline off this
  should re-measure in hex - `sqrt(el(e(V), k, k))` through `%21x`, not `_se[]` inside a
  program, which is what silently failed here.

## 8.6 What is still not measured, after this round

`poisson`/ppmlhdfe separation; weighted runs; `subgroups()`; `contreat()`/`lattice()`;
`bootdisplay(bca)`'s jackknife over a dead-cluster frame; `bootsave()` file contents;
HV-BOOT-05's two-live-cluster extreme; and — still the one that matters most for
judging SMP-3 as a *method* rather than as a bug fix — a **coverage simulation** on a
mixed-regime design, before and after. Everything in sections 8.2-8.4 is an identity or
an A/B on one draw stream, which is the right evidence that the *mechanism* is what these
findings say it is, and is not evidence about size or coverage.
