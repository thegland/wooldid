# GTE-3: where the conservative band came from

The author ruled SHIP with *"a conservative band"*. Rather than take the proposal's `1e-12`
on faith or move it by feel, both populations the band has to separate were measured. The
screen was instrumented at its own call site (`ado:1800`) on the pinned build `62b121c`, and
every fit it sees wrote one line.

The deciding statistic is

    r  =  sqrt( max|e(V)| ) / max( finite |e(b)| )

and the screen fires iff `r <= TOL`. Healthy fits sit high; residue fits sit low.

## The healthy population — 8.4 orders of margin

135 stage-1 fits across the 59 blessed battery configs:

| | r |
|---|---|
| minimum | **2.2803e-04** (`cont_ss`, `cont_sg`; `cont_basic` 2.4413e-04) |
| median | 6.96e-02 |
| maximum | 5.62e-01 |
| minimum over replication fits | 4.3723e-02 |

Adversarial search for a *healthy* design nearer the band failed on every angle tried: two
clusters with ordinary noise gives r = 3.7e-02, three clusters 3.5e-03, a regressor rescaled
by 1e12 gives 0.359 and by 1e-12 gives 0.021, and a control that is exactly `1000*y` gives
3.1e-05 — the anchor shrinks with the coefficient, so that case fails **safe**.

The smallest r reachable on any fit that still carries a residual at all is **2.555e-09**, and
that is not a healthy run: it is a zero-noise DGP reproducing its own outcome, floored by
`reghdfe`'s convergence tolerance rather than by the data. Residual sd of 1e-9, 1e-10, 1e-11,
1e-12, 1e-14 and exactly 0 all return a bit-identical `max|e(V)| = 2.0593e-16`.

So: **8.4 orders** below the nearest real battery fit, **3.4 orders** below the most degenerate
fit that still has a residual.

## The residue population — and the limit the proposal did not state

| N (obs) | max\|e(V)\| | r | posted ATT se | margin under TOL = 1e-12 |
|---|---|---|---|---|
| 480 (the motivating shape) | 7.287e-29 | 3.812e-15 | 4.13e-16 | **+2.42 orders** |
| 4,800 | 7.790e-27 | 3.677e-14 | 2.75e-14 | +1.43 |
| 16,000 | 2.325e-25 | 1.577e-13 | 1.21e-14 | +0.80 |
| 24,000 | 2.114e-25 | 1.980e-13 | 2.03e-13 | +0.70 |
| 120,000 | 4.190e-24 | 8.960e-13 | 3.93e-13 | +0.05 |
| 480,000 | 7.896e-23 | 3.891e-12 | 8.04e-13 | **-0.59 — NOT CAUGHT** |

The residue is accumulated rounding, so it grows **linearly in the row count**: `r/N` is
7.47e-18 to 9.86e-18 across three orders of N, i.e. `r ~ 8.0e-18 * N`, crossing 1e-12 at about
**1.2e5 rows**. At 480,000 rows the run reports an ATT of 0.9997 with se 8.0e-13 and the screen
stays silent.

**This is a real gap and it is stated in the code comment rather than hidden.** No *constant*
band repairs it: the exact-fit floor falls as about 2.0e-7/sqrt(N) while residue rises
linearly, and the two classes meet near **8.5e6 rows**, above which no fixed tolerance
separates them at all. An N-aware floor is the shape of that remedy; it is not built.

## Why not a different TOL

| TOL | battery fits that fire (of 135) | orders under the exact-fit floor | residue escapes above |
|---|---|---|---|
| 1e-11 | 3 — the same 3 that fire today | 2.41 | ~1.2e6 rows |
| **1e-12** | **3 — the same 3 that fire today** | **3.41** | **~1.2e5 rows** |
| 1e-13 | 3 — the same 3 | 4.41 | ~1.2e4 rows |

No measurement distinguishes 1e-12 from 1e-11 on the false-positive side — both fire on zero
new battery fits. 1e-12 is taken because it is the value the ruling was made against and the
tie-break was toward not firing. Going lower is not more conservative in any useful sense: it
spends residue coverage that is already thin at moderate N to buy false-positive margin that
is already 3 to 8 orders wide.

## Equivariance held

The relative anchor is what makes the floor independent of the units of y, and that was
tested rather than assumed. On a healthy arm with y scaled across **18 orders** (x1e-9, /1e3,
base, x1e3, x1e9), r = 5.5788e-02 to **8 significant figures** (ratios 0.99999994 to
1.00000009). On the residue arm across 12 orders, r ranged 3.73e-15 to 4.00e-15 — a 5% drift,
expected and harmless, since the residue *is* rounding noise and rescaling y changes the
rounding pattern. Five percent is nothing against margins measured in orders.

## What the implementation had to get right

1. **Finite filter on the anchor.** Mata's `max()` over a vector holding a missing returns
   missing, and `x <= .` is true for every finite `x` — unfiltered, the screen would fire on
   every run whose `e(b)` carries a missing. Measured: 0 of 135 battery fits and 0 of ~45 probe
   arms actually had one (`reghdfe`, `ppmlhdfe` and `regress` return omitted collinear terms as
   exact 0, confirmed against a constant control, an exactly collinear control, a control with
   50 missing values, a separation poisson dataset and three pathological panels). The guard is
   kept anyway: the failure mode is total and the guard is free.
2. **Element-wise, not `select()` on the matrix**, which selects whole rows or columns. The
   anchor vectorises first.
3. **Empty selection returns 0, not missing.** The predicate then collapses to
   `max|e(V)| <= 0`, which is exactly the old test — so the new screen is a strict **superset**
   of the old one and nothing that fired before stops firing.
4. **Nothing left in the user's Mata session.** A `cap mata: mata drop` on a following line
   does not run if the assignment aborts mid-statement, so the anchor is a named function
   (`wooldid_vzanchor`) rather than an inline temporary. Same reasoning as `wooldid_Mtmp` (D-3).

Unit-tested directly: `(1,-5,3) -> 5`, `(1,.,3) -> 3`, `(.,.) -> 0`, absent matrix `-> 0`.

## Wording

An exactly zero covariance keeps the wording it has always had, **byte for byte** — there the
standard errors really are missing, and `test/test_amescreen.do:146` asserts that string. A run
caught by the new floor gets accurate wording instead, in both cautions: the matrix is named as
cancellation residue rather than as zeros, and the standard errors are described as residue
printing as numbers of order 1e-15 rather than as missing values.

## Not covered

* The screen never runs under `fastnose` or under plain `permute()` (the no-SE path). 10 of the
  59 battery configs record no stage-1 fit at all.
* Under `bootstrap()`/`permute()`-with-analytic-SEs the block runs once per replication and
  replications are quiet, so a firing there prints nothing. 86 replication fits measured, min
  r = 4.37e-02, nowhere near the band. Compute cost only.
* The residue growth law is measured on **one** family: K=1, two clusters, `i` = cohort =
  cluster, `reghdfe`, unweighted. Not measured under `ppmlhdfe`, under multiway `cluster()`, or
  with weights.
