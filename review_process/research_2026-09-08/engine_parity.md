# Engine parity: should bootstrap() and permute() behave identically?

Research commissioned 2026-09-07 by the author, whose question was: "It is not clear to me the
two cases should be identical. Please research this more." Six lenses: a first-principles lens, three
item cohorts covering the thirty-one differences the consistency sweep's P7 package lists, an
adversarial lens arguing parity is the wrong goal, and a user-model lens ranking practical confusion.

## Verdict

Across all lens-item votes: **59 principled, 43 incidental, 4 unclear**. Recommendations:
**73 keep-and-document, 27 harmonize, 5 needs-author, 1 keep-silently**.
The sweep's P7 framing, which treats parity as the goal, is not supported: the majority of the
differences follow from what the two engines ARE.

## The three mechanical facts that generate the legitimate differences

1. **Recentring.** Bootstrap draws are sampling draws centred at the observed estimate, so any null
   reference must be manufactured by recentring, which is an asymptotic device. Permutation draws are
   null draws by construction, nothing is recentred, and the observed statistic is a member of its own
   reference set.
2. **Reweighting.** A bootstrap replication carries duplication or Dirichlet weights, so a replication's
   standard error is a different functional of the data than the observed one. A permutation replication
   relabels onset over the same rows, so it is the same functional.
3. **The assignment is the randomized object.** Anything keyed on onset or treated status has no
   permutation distribution at all, and the randomization unit must nest the cohort variable.

Everything that does not trace to those three is incidental: threshold numbers, message wording, which
engine happened to get a caution or a stored object first.

## Differences that must NOT be harmonized away

- Completion-failure REFUSAL levels (CS-45). permute's max(20, R/2) floor is a reference-set/exactness constraint — failures are selected on the reassignment being inestimable, so they delete a non-random slice of the reference set and the combinatorial resolution 2/(R+1) degrades. Any bootstrap floor would be a different number for a different reason (Monte-Carlo error, which shrinks in reps()). Do not give the bootstrap permute's number. permexact's any-failure caution is principled for the same reason.
- The domain of the subgroups() screens (CS-52). Analytically it is the observed treated units; under permute it is every unit the randomization can treat, because a subgroup variable well-formed only on today's treated units is ill-formed for the reference distribution. Do not downgrade the permute widening to a caution.
- Substitutability of the no-analytic-SE state (CS-53, CS-94). fastnose supplies no substitute for the missing covariance; permute's replications supply a permutation metric that the adversarial and joint quadratic forms consume. The two no-SE states are different states wearing one name, and permute's default is right. (Scope note: the bootstrap's fastnose refusal is strictly load-bearing only where the observed analytic SE is consumed — boottstat, e(V)/e(V_es_*), honestdid.)
- The pretrendpower() refusal under permute (CS-92, CS-95). A metric used INSIDE a permuted statistic needs only positive-definiteness; Roth's power calculation consumes the covariance as an absolute precision with no permutation reference behind it, so it needs a sampling covariance. The permutation covariance is a conditional null-relabelling metric, so it is the wrong kind of object — the refusal stands even though its stated reason does not.
- Blanking assignment-keyed lattice cells under permute only (CS-96). The lattice quantile is conditioned on ttre: the bootstrap holds ttre fixed and moves the bins only through sampling variation in the treated units' dose distribution, which is correct uncertainty propagation for a data-dependent estimator; permute reassigns ttre, so cell k is a different referent per replication. Porting the drift list into wooldid_bootcellsx would discard correct statistics.
- Refilling the ame containment cells under the resampling engines (CS-97). The screen protects against an analytic clustered delta-method variance; the coefficient-draw bootstrap does not consume it, so refilling is sound — and the one surface that does consume it (boottstat) already re-blanks. Do not OR the containment flag into the rewiring's exclusion vector.
- THE NULL IS MANUFACTURED VS GIVEN. The bootstrap must recentre its draws to obtain a null reference (ado:12724, 6092-6146); permute's draws are already null draws and nothing is recentred (ado:13360-13366). Every downstream asymmetry about p-value conventions, interval meaning, and what an SD means descends from this. Do not harmonize any of them into a single 'resampling' vocabulary.
- ADD-ONE VS PLAIN SHARE. Permute's (1+m)/(n+1) is an exactness result: under the sharp null the observed assignment is exchangeable with the permuted ones and belongs in its own reference set. The bootstrap's plain 2*min(m0,m1)/n has no such reference set to join, so add-one there would be a conservatism choice, not exactness — the code says exactly this at ado:13153-13160 and the author ruled it on 2026-09-07. Consequence that must also be preserved: a bootstrap coefficient p can print exactly 0; a permutation p cannot (except under permrawp, which deliberately reproduces ritest's plain share).
- A P-VALUE FLOOR THAT MONEY CAN BUY VS ONE IT CANNOT. The bootstrap's resolution 2/n shrinks with reps() and is entirely under the user's control; permute's floor is set by the design's assignment support M (ado:5385, wdp_npd at 11349) and no number of replications can move it below 2/M. This is why permreps() has a hard floor and reps() correctly has only a caution (author ruling CS-20, 2026-09-07). Keep both.
- EXACT ENUMERATION HAS NO BOOTSTRAP ANALOGUE. permexact switches to plain shares because the observed assignment is literally a member of the enumerated set (ado:13372-13375, the exk branch at 13627-13632), and e(perm_exact) then suppresses the Monte-Carlo precision record because the shares are not estimates (ado:13468-13471, 9672). There is no bootstrap state in which the reference set is the population of possible resamples, so e(perm_exact), wdp_npd and the enumeration cautions have no twin and must not be given one.
- AN INTERVAL DOES NOT MEAN THE SAME THING. A bootstrap percentile/BC/BCa/normal interval is an approximate confidence set for the estimand with asymptotic coverage. Permute's interval is a shift interval that inverts the equal-tailed test under a fixed-zero-null pivotality approximation, is not a sharp-null randomization inversion, is calibrated only near the null, and widens with the true effect because the relabelled outcomes carry it (ado:13366-13376, 13480-13490, footer 9668). They are different objects with the same shape and must keep different hedges; the off-centre guard that blanks the interval while keeping the p-value (ado:13481-13487) has no bootstrap counterpart and needs none.
- A NULL BAND IS NOT A CONFIDENCE INTERVAL. e(perm_lb_*)/e(perm_ub_*) are the signed level() quantiles of the null draws (kernel rows 11-12, ado:13387-13389) — the region the statistic occupies under the null, not a region for the estimand. The bootstrap has no such object because its draws are not null draws. The naming defect (CS-57) is real; the absence of a bootstrap twin is not.
- SD OF DRAWS: STANDARD ERROR VS NULL DISPERSION. sqrt(variance(draws)) under the bootstrap estimates the estimator's standard error and is legitimately printed in the `se` column and used for the normal interval (ado:13130-13134). Under permute the same arithmetic gives the dispersion of the statistic under the relabelling null, which is not a standard error — which is precisely why permute keeps the analytic number under the label `se_analytic` and posts its own dispersion separately as e(perm_sd). e(boot_sd) and e(perm_sd) are not twins.
- SE_R IS A DIFFERENT FUNCTIONAL UNDER THE BOOTSTRAP AND THE SAME ONE UNDER PERMUTE. Duplication or Dirichlet weights make a replication's standard error a different functional of the data than the observed one (ado:5716); relabelling onset over unchanged rows does not. This makes boottstat's poisson and bayes refusals principled with no permtstat analogue needed, and it is also why boottstat with cluster() must run the physical resample-and-re-identify leg so the SE clusters on the RESAMPLED identity (ado:5799-5819) — a leg permute never needs, because it never duplicates a row.
- TWO DIFFERENT EXCHANGEABILITY ASSUMPTIONS, NOT ONE ENGINE THAT NEEDS IT AND ONE THAT DOES NOT. The pairs cluster bootstrap assumes clusters are exchangeable as SAMPLING draws (fails with few or atypical treated clusters, MacKinnon-Webb 2017/2018, ado:5855). Randomization inference assumes clusters are exchangeable in ASSIGNMENT — any cluster could have received any onset (fails when treated clusters are heterogeneous in variance, MacKinnon-Webb 2020, ado:5470, sthlp:394). Same shape, orthogonal failure modes, orthogonal remedies. This is why the bootstrap's referral to permute() at ado:5855 is a genuine hand-off rather than a clean bill of health, and why the two engines correctly count different things: the bootstrap counts clusters and treated clusters, permute counts possible assignments (wdp_caut0/1/2). Neither count is the right diagnostic for the other engine.
- A FAILED REPLICATION MEANS DIFFERENT THINGS. Dropping a failed bootstrap resample conditions the retained distribution on estimability, which is not the sampling distribution the engine is trying to approximate — the code already says so at ado:5855 ('the retained distribution is conditional on that event'). So ANY failure attacks the target, and a caution on any failure (ado:8220) is right. Under the sharp null the outcomes are fixed, so the set S of estimable assignments is a function of the assignment alone and the observed assignment is in S; the test restricted to S is an exact CONDITIONAL randomization test. Permutation failures therefore cost resolution and interpretability, not validity, and a fractional threshold (ado:6969) is right. The sweep's 'the user is warned loudest where the problem is smallest' inverts the statistics.
- ANYTHING KEYED ON THE RANDOMIZED OBJECT HAS NO PERMUTATION DISTRIBUTION. gteffects cells are keyed by cohort onset and the replications reassign exactly that key, so blanking is the only honest treatment (sthlp:967); subgroup screens must hold on every in-sample unit because any cluster can be assigned treatment in a replication (ado:5507-5530); the randomization unit must nest i because one onset is written per cluster (ado:5478); a design with one possible assignment is refused rather than cautioned (ado:5549, 6753). The bootstrap has no analogue of any of these and should not acquire one.
- STRATIFICATION IS A VALIDITY REQUIREMENT ON ONE SIDE AND AN EFFICIENCY DEVICE ON THE OTHER. permstrata() exists because a reference distribution that ignores how onset was actually assigned is the wrong reference distribution; a stratified bootstrap, by contrast, changes accuracy rather than validity. The absence of a bootstrap strata option is therefore not the same kind of gap as the absence of permstrata would be, and 'parity' is the wrong frame for it.
- BIAS CORRECTION AND ACCELERATION ARE SAMPLING-DISTRIBUTION CONCEPTS. e(boot_z0), e(boot_accel), e(boot_jk_completed), ties and the whole BC/BCa family correct the median-bias and skewness of an estimator's sampling distribution. Null draws have no such bias to correct. These objects correctly have no permutation twin.
- WHAT EACH ENGINE MUST REFUSE FOLLOWS FROM WHAT IT CANNOT SUPPLY. The bootstrap must refuse combinations that would report a non-bootstrap quantity under a bootstrap header (customvce() for the coefficient-draw families, ado:5768) and studentization where se_r is the wrong functional (ado:5716). Permute must refuse designs with no randomization support (ado:5549, 6753), randomization units that do not nest i (ado:5478), and — as shipped — pretrendpower(), because Roth (2022) consumes a SAMPLING covariance and the permutation metric is a null-relabelling one (ado:5931-ish refusal; the covariance's real character is stated at 13366-13372). What neither must refuse is an option the other happens to have gated first.
- The bootstrap resamples whole clusters carrying their observed onset, dose and subgroup value; permute reassigns onset. This single fact generates most of the legitimate divergence in my set and should be stated once, in the shared inference preamble, as the rule that explains the rest.
- permute() widens the four subgroups() domain screens from treated rows to every in-sample row (wooldid.ado:5494-5522); the analytic path and bootstrap() do not (wooldid_sgdom:10204-10255; no subgroup screen in wooldid_bootctl 5575-5900). Bootstrap's silence is correct — a never-treated cluster stays never-treated in every replication, so its subgroup value is never consumed. Do not widen the bootstrap or the analytic path for symmetry.
- boottstat is refused with poisson (5716) and bootstrap(bayes) (5720); permtstat has no such gate and needs none. Bootstrap replications carry duplication or Dirichlet weight, so se_r is a different functional of the data than se_obs (measured E[se_r^2]/se_obs^2 of 1.44-1.83); permutation replications relabel onset without reweighting any row, so the functional is identical by construction.
- gteffects inference columns are bootstrapped under bootstrap() and blanked under permute() (5945-5977 vs 7558-7572, disclosed by e(perm_gt_blank)). The cells' index is cohort onset and the replications reassign exactly that index; there is no permutation distribution to report and filling from the analytic run would be wrong.
- permute() refuses contreatwithin (5315) and contreatcontrols(untreatedZero) (5325); bootstrap() supports both and deliberately forwards contreatwithin into every replication (comment at 293-295, R2 finding 5). Resampling preserves each unit's onset-and-dose pairing, so untreatedZero's dose-zero-outside-treatment premise and contreatwithin's comparison group both survive; relabelling onset destroys both.
- fastnose is permute()'s default (sthlp:267, 441) and bootstrap()'s hard refusal (5760). Randomization inference does not consume the observed analytic standard error; a bootstrap has nothing to attach inference to without it. Two states, one word — do not unify the gate.
- For a 0/1 treatment only dydx and eydx are meaningful transformations; dyex and eyex differentiate with respect to log x and are degenerate on a dummy (code comment at 1920). Do not add a four-valued elasticity option for the binary treatment. Separately, the cell-collapse eligibility rule is already single and symmetric — divide-by-prediction is ineligible, linear-in-dose is eligible (4635, 4668, stated at 4682) — and the sweep's claim of a binary/continuous eligibility split does not survive.
- Under either engine the cfx plots are redrawn by twoway from the rewired e(cfx*) matrices rather than by marginsplot (10771-10877, gates at 2345/2389/2438/2478). marginsplot can only plot the last margins results, which under an engine no longer carry the reported inference. The two engines agree completely here; only the analytic path differs.
- A permutation step-down is exact under the global sharp null of no effect at any horizon (wooldid_permstep, 13652-13714, with the exact branch at exk); a recentred bootstrap step-down built from wooldid_bootqf's draws would be asymptotic and would test a different null. If the bootstrap twin is ever built, it is a second statistic and needs its own footer sentence — it is not the same object ported.
- Fast mode as permute's default and as a bootstrap refusal (CS-3, CS-94, CS-53). The bootstrap's observed run is the centre of its reference distribution and, under `boottstat`, the studentizing denominator; randomization inference consumes no observed analytic SE at all. Two genuinely different states wearing one name. Do not make `bootstrap()` accept `fastnose`, and do not make `permute()` compute analytic SEs by default.
- `boottstat`'s poisson and `bootstrap(bayes)` refusals having no `permtstat` analogue (CS-22, CS-107). Bootstrap replications carry duplication or Dirichlet weights, so a replication's `se_r` is a different functional of the data than `se_obs`; permutation replications relabel onset without reweighting a single row, so that failure mode cannot arise. The absence of a `permtstat` gate is correct, not an oversight.
- `pretrendpower()` supported under `bootstrap()` and refused under `permute()` (CS-19, CS-92, CS-95). Roth (2022) consumes a SAMPLING covariance. The bootstrap supplies one; the permutation covariance is a null-relabelling metric that the joint and adversarial quadratic forms can legitimately use and Roth's power calculation cannot. The refusal must stand — only its stated reason ("randomization inference produces none", ado:5338) is false and must be rewritten.
- `gteffects` cells blanked under `permute()` (CS-128). The cells are keyed by cohort onset and the replications reassign exactly that key, so no permutation distribution of a fixed quantity exists. Blanking beats filling from the analytic run, which would put an analytic number under a permutation header. Only the unconditional slogan at sthlp:966 needs qualifying.
- The widened `subgroups()` screens under `permute()` (CS-52, CS-106), including the `permstrata()` composition caution. Any cluster can be assigned treatment in a replication, so a subgroup variable well-formed only on today's treated units is genuinely ill-formed for the randomization. Both proposed harmonizations — tightening the analytic screen or downgrading permute's to a caution — are worse than the status quo.
- `cluster()`'s change of meaning and of requirements under `permute()` (CS-27). A variance may be clustered finer than `i`; a randomization unit cannot, because each replication writes one onset to every observation of a cluster. The requirement difference follows from the mechanics; only the overload and the divergent error wording need work.
- Blanking the assignment-dependent cfx lattice types under `permute()` and not under `bootstrap()` (CS-96). A reassignment changes which units are treated by construction, so `lattice_k` is a different estimand in every replication; a resample's quantile is a statistic of the resample, so the bootstrap is correctly propagating the bins' own estimation uncertainty. Do NOT port the drift list into `wooldid_bootcellsx` — the sweep filed this as indefensible and I think that is wrong.
- The EXISTENCE of a permutation completion floor and of the `permexact` any-failure caution, against the bootstrap's no-floor policy (CS-32, CS-45). A permutation reference set that has lost draws is conditional on estimability — a function of the assignment being tested — so a floor is a correctness guard; a bootstrap losing draws is only losing resolution. The author has already ruled this twice in opposite directions on purpose (F030, F036, CS-20). Only the caution THRESHOLDS are policy.
- The engines' exemption from the analytic joint-test screen (CS-15). The screen refuses because the analytic covariance is degenerate at cluster nesting `i`, and its own text recommends the engines as the remedy; the engines do not use that covariance for those tests.
- The bootstrap refilling AME cells the analytic containment screen blanked (CS-97). A cluster bootstrap does not rely on the within-cell variance the analytic screen protects against, and the package's own caution (ado:10647) recommends exactly the engines that refill. Withholding the resampled number would withhold a sound one.
- Permutation-only step-down (CS-108) as a shipped decision rather than a statistical necessity: Romano-Wolf is routinely bootstrapped, but the author ruled it permutation-only under PS-45 with simultaneous bands covering the bootstrap instead. Treat as settled, and document rather than build.
- Studentization is the only inference path that consumes the OBSERVED analytic standard error, and both engines already gate it identically — ado:5365 refuses permtstat/permtci with fastnose, ado:5760 is required under boottstat. Do not remove either gate; the shared rule is 'the studentized statistic needs its denominator', not 'the bootstrap needs analytic SEs'.
- boottstat's poisson (ado:5716) and bootstrap(bayes) (ado:5720) refusals, and its cluster-nesting requirement (ado:5819), have no permtstat analogue and must not be given one: a bootstrap replication reweights rows, so se_r must be the same functional of the reweighted data as se_obs is of the original, and sampling weights, Dirichlet mass and frequency-reweighted pooling each break that; a permutation replication relabels onset and reweights nothing, so the failure mode cannot arise.
- Only bootdisplay(percentile) survives boottstat (ado:5733, 5745). A studentized draw has no standard deviation in coefficient units for a Wald family to rest on, and the bias-corrected shift applied to studentized quantiles and then reflected moves the interval against the median bias. The option is legitimately four-valued on one path and single-valued on another.
- pretrendpower() belongs to the bootstrap (sthlp:485; the diagnostics run after rewiring so Roth's formulas consume the bootstrap event-study covariance) and must stay refused under permute (ado:5338). Roth (2022) consumes a SAMPLING covariance; permute has only a null-relabelling fixed metric (ado:7271). Only the refusal's stated reason should change, never the refusal.
- e(V_es_*)'s provenance legitimately differs by engine — bootstrap covariance under bootstrap() (ado:8697-8712), nothing under default permute, analytic under permanalyticse with the footer saying so (ado:9669-9670). honestdid needs a sampling covariance and each engine posts the only correct object it has; a permutation e(V_es_*) would be a substantive unresearched claim.
- The engines' exemption from the SI-A1 analytic joint-test screen (ado:1259-1260) is the screen working, not a hole in it: the screen indicts the analytic CRVE's inability to carry within-cluster cross-horizon variation, and neither engine uses that covariance for those tests. Permute's own requirement that cluster() nest i (ado:5478) puts every permute jointtests run inside the refused analytic configuration by construction — a variance may be finer than i, a randomization unit may not.
- The DIRECTION of the failed-replication policy: caution at any failure under the bootstrap (ado:8220), because excluding failures breaks the premise that the resample distribution matches the empirical one; a threshold plus a completed floor under sampled permutation (ado:6961, 6969), because estimability under a relabelling is a y-independent design event, the observed assignment is always retained, and the test stays exact per element on the smaller set; and caution at ANY failure under permexact (ado:6968), because completeness is what the exact self-membership and 2/M-floor readings rest on. Only the thresholds themselves are calibration.
- cluster()'s four meanings and their differing requirements (ado:4740-era impvalues, 5478 permute, 5818-5819 bootstrap). A variance may be clustered finer than i and may be multi-way; a resampling unit that duplicates whole units and a randomization unit that writes one onset per cluster may be neither. Under permtstat the variable doing double duty is MacKinnon-Webb (2020)'s recommendation, not a conflation.
- The absence of a count-based ASYMPTOTIC caution under permute. Randomization inference has no G-to-infinity requirement, so the bootstrap's 5836/5855 cautions must not be ported as written. (What is missing is a different caution — permute's own exchangeability and resolution limit — which is the incidental part of CS-10/CS-39.)
- The kind of covariance each engine produces. bootstrap() yields a SAMPLING covariance; permute() yields a null-relabelling metric (built in wooldid_permjnt, ado:7266). Quadratic-form tests (joint pre-trend, subgroup equality, adversarial line) are defined on either; Roth (2022) power calculations and honestdid's Rambachan-Roth robustness region are defined only on the former. This single fact generates CS-19, CS-53, CS-92, CS-95 and the dangerous half of CS-14 — and it is why permute() must keep refusing pretrendpower() and must NOT start posting e(V_es_*).
- What a missing surface means. Under permute()'s default the event-study b/V matrices are absent, so honestdid, lincom and test return rc 111. That absence is a refusal, not an omission: it is the only thing standing between a user and a silently invalid robustness region. Manufacturing the surface for parity converts a clean error into a wrong answer with no diagnostic.
- What a failed replication means. A lost bootstrap draw inflates Monte-Carlo error; a lost permutation draw removes an element of the reference set, and under permexact destroys the exactness claim outright (ado:6969's permexact branch). Hence permute's hard completion floor (ado:6961) and the bootstrap's absence of one (F030) point in opposite directions on purpose, and P7(ii)'s 'harmonize the failure thresholds' would reverse one standing ruling whichever direction it chose.
- What studentization requires. Bootstrap studentization needs se_r to be the same functional of the reweighted data that se_obs is of the original — broken by poisson sampling weights (ado:5716) and by Dirichlet mass (ado:5720). Permutation studentization needs only a consistent scale; replications reweight nothing, so the failure mode has no analogue and permtstat correctly carries no poisson or bayes gate.
- What an assignment-dependent statistic is. A baseTreated dose bin is a function of the treatment assignment. Under permutation that makes the cell a moving target across replications, so its inference columns are correctly blanked (ado:7636-7684). Under the bootstrap the treated set is fixed and the bin boundaries are estimated, so recomputing them per replication is the plug-in bootstrap of a data-dependent-partition estimand — correct, and porting permute's gate into wooldid_bootcellsx (which has no lattype parameter at ado:5928) would blank valid intervals.
- What the randomization support requires of the data. permute() widens the subgroups() screens to every in-sample row (ado:5494-5516) because any cluster can be assigned treatment in a replication. That strictness is a property of the randomization, not of the data, so running the widened screens analytically would refuse correct runs; downgrading them to cautions under permute would let replications mix subgroup compositions.
- What the analytic containment screen protects. The AMESE R1 screen guards a delta-method AME standard error the design cannot support. A cluster bootstrap does not consume that quantity, so refilling those rows is legitimate and the package's own caution (ado:10647) recommends exactly that switch. Blanking the bootstrap rows 'for consistency' would withhold sound numbers and contradict printed advice.
- What cluster() can be. A variance may be clustered finer than i; a randomization unit cannot, because a unit carries one onset. permute()'s mandatory single nesting cluster (ado:5421) and the bootstrap's optional one are each right for their feature, and the difference is mechanical, not stylistic.
- What a multiplicity adjustment guarantees. permute()'s max-|studentized| step-down is exact under the sharp null because every horizon's draws come from one reference set. A bootstrap step-down is buildable (Romano-Wolf's original is one) but controls FWER only asymptotically; printing it in the same footer slot under the same wording would transfer an exactness claim it does not have.
- What the observed run is for. permute()'s observed run is the comparator inside its own reference distribution and consumes no analytic SE, so fast mode is the right default (ado:4953-4964). The bootstrap's observed run is the centre of the resampling distribution and feeds e(V_analytic), bootdf()'s df alignment and pretrendpower()'s hbaronly re-entry, so it is not disposable. Same three words, two structurally different roles.
- Structural unreachability is not a missing gate. customvce() cannot co-occur with permute() at all — wooldid_validate refuses customvce() with cluster() at ado:4297-4300, permute() requires cluster() at ado:5421, and validate runs first (permctl is called at 4523). A 'parity' gate for that combination would be code whose message can never print.
